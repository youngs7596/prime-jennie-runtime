### 2. 그래픽카드 — 정전 때와 다른 고장이었다

저녁 8시에 재부팅됐을 때 카드는 멀쩡히 붙었고 전력 제한 200W 도 자동으로 걸렸다. 그런데
**20분쯤 뒤 아무도 케이블을 안 건드렸는데 혼자 버스에서 떨어졌다.** 다시 꽂으니 썬더볼트
인증과 카드 인식까지는 되는데 드라이버가 안 붙었다. 여기서 드라이버를 강제로 붙이려 하면
커널 안에서 영영 안 끝나고(같은 오류가 5초마다 무한 반복), 그 작업을 한 컨테이너는 강제
종료로도 안 죽는다. 재부팅도 그 작업에 붙잡혀 5분쯤 걸렸다.

**결국 재부팅 + 카드 전원 차단으로만 풀렸다.** 다시 연결하자 인식·200W 자동 적용·추론까지
한 번에 정상 복귀했다(소비 130W, 22GB 점유). 원인은 못 가렸다. 케이블일 수도, 박스 전원일
수도, 썬더볼트 링크일 수도 있어서 며칠 지켜봐야 반복인지 한 번인지 갈린다.

곁가지로 두 가지를 알았다. 하나, 계정이 도커 그룹에 있어서 도커를 거치면 비밀번호 없이
root 작업이 된다 — 커널 로그 읽기 같은 진단엔 편했지만 카드 바인딩엔 쓰면 안 된다(굳는다).
둘, **"카드가 빠지면 뉴스 추출이 조용히 실패한다"는 기존 전제가 이번 관측과 안 맞았다.**
카드가 사라져 있던 20:29~20:43 사이에도 뉴스 이벤트가 계속 쌓였고 전부 로컬 모델 이름으로
기록돼 있었다. 왜 그런지는 안 가렸다. 다음에 카드가 빠지면 그 구간을 먼저 확인해 이 전제를
확정하거나 지워야 한다.

### 3. 야간선물 웹소켓 스모크 — 죽었던 지표가 살아났다

화요일 밤 10분을 돌려 7-26 이 남긴 미검증 항목을 판정했다. **근월물 체결 프레임 325개를
받았다.** 같은 10분 동안 조회 API 는 미결제약정·거래량·가격이 한 자리도 안 움직였는데
웹소켓에서는 가격이 3.4포인트 움직였다. "조회 API 가 야간에 눈이 먼다"는 판정이 추론이
아니라 대조 관측으로 확정됐다.

**결정적인 건 따로 있었다.** 프레임 안에 야간 미결제약정만 오는 게 아니라 **주간 마감 대비
증감이 이미 계산돼서 실려 온다.** 우리가 빼서 만들려던 숫자를 증권사가 그냥 주고 있었다.
산술로 두 번 독립 확인했다 — 관찰 시작 때 164,214 − 163,821 = 393 이고 증감 칸이 −393,
끝날 때 164,214 − 163,845 = 369 에 증감 칸이 −369 였다. 8-04 밤 값은 −369 계약이다.

차월물은 10분 내내 프레임이 하나도 안 왔다. 야간엔 근월물만 거래되는 것으로 보인다.
롤오버 중화용 두 계약 합산 규칙이 만기 주간(9월 초)에 야간에도 성립하는지는 아직 모른다.

### 4. 상시 수집 구축 (commit 11766f9 + 33bd4b0, migration 030)

야간장 동안 계약별로 분 단위 미결제약정을 남긴다. 세션 마지막 값만 찍지 않은 이유는
포지션이 초저녁에 접히는지 새벽에 접히는지까지 보려는 것이고, 분 단위여도 한 밤에 계약당
660행을 안 넘는다.

**주간 스트리머에는 얹지 않았다.** 그쪽은 매매 가격 스트림과 실시간 체결·호가 적재가 물린
공용 자원이라 선물 구독을 끼워 넣으면 장애 반경이 매매까지 넓어진다. 야간장 18시~새벽 5시와
주간 스트리밍 8시 50분~15시 35분이 안 겹치므로 연결을 시간으로 나눠 쓴다.

날짜는 야간장이 시작된 거래일로 붙인다. 자정 넘긴 체결은 하루를 당겨 기록해 같은 날짜 안에
주간 마감과 야간 관측이 나란히 놓인다. 휴장일엔 행을 아예 안 남기고, 거래일 판정은 그 날짜에
주간 마감 스냅샷이 있는지로 한다 — 새벽 5시에 '오늘'을 기준으로 따지면 금요일 밤 세션이
토요일 새벽에 끝나는 구조와 어긋나기 때문이고, 기존 수집기가 쓰던 가드를 그대로 가져왔다.

**중간에 구멍을 하나 찾아 고쳤다.** 처음 코드는 체결이 올 때마다 야간장이 열려 있는지를
확인했는데, 새벽엔 체결이 몇 분씩 끊긴다. 마지막 체결 뒤에 5시가 지나도 못 알아채고 연결을
물고 있게 되고, 그 상태로 아침이 되면 8시 50분에 붙는 주간 스트리머와 같은 계정으로 겹친다.
시간대를 나눠 쓴다는 이 설계의 전제가 바로 거기서 깨진다. 감시 역할을 따로 두어 창이 닫히면
연결을 직접 끊게 했고, 체결이 하나도 없는 상황을 흉내 낸 테스트로 실제 종료까지 확인했다.

상태 조회에는 일부러 수신 프레임 수를 넣었다. 구독 승인만 보고 "붙었다"고 판단했다가 데인
게 이 프로젝트에 세 번 있었다(투자자별 선물의 정상응답 전항목 0, 빈 키로 성공 기록한 공시
수집, 일요일에도 나오던 이 웹소켓 승인). 야간장 중에 이 숫자가 0 이면 승인이 뭐라 답하든
데이터는 안 흐르는 것이다.

테스트 23개를 새로 넣었고 전체 1,709개가 통과한다. 게이트에는 여전히 연결하지 않았다.
