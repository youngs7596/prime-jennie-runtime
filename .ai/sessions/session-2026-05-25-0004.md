# 세션 정리 — 2026-05-25-0004

이번 세션은 "어떤 종목을 노려야 할지" 라는 큰 질문에서 출발해서 prime-jennie 가 지금까지 쌓아온 데이터를 다 뒤져본 분석 세션이다. 결론은 명확하다. v2 시기 (2025-11 ~ 2026-03) 의 실 매도 245 건은 평균 +2.5% / 건 승률 64% 였고, v3 LLM 시기 (4-18 ~ 5-22) 의 132 건은 평균 -2.2% / 건 승률 27% 였다. 같은 시스템 계보인데 결과가 정반대로 갈린 이유는 두 가지로 모인다. 첫째 v3 결정론 코어 (5-22 이후) 의 supply_demand 점수가 universe 평균보다 평균 +3.5 만큼 높은 종목으로 자동 쏠려 거래대금 큰 반도체/IT 대형주만 뽑힌다는 점, 둘째 5월 시장 자체가 v2 시기와 결이 달라서 금융주는 자연 약하고 자동차·항공·통신·산업재가 강한 국면이라는 점이다. 다음 세션의 1순위는 quant.py 의 supply_demand 가중치 또는 정의를 손보는 것이다.

## 1. 프로젝트 개요

prime-jennie-runtime + 별도 repo prime-jennie-control-ui. 백엔드는 dashboard FastAPI, 데이터는 v3 Postgres + Redis. v3 컨테이너 스택은 MS-01 호스트에서 실행되고, 코드 push 가 ghcr 빌드와 deploy 워크플로우를 자동 트리거한다. 5-22 결정론 코어 전환 이후 매매 진행 중. 5-25 오늘은 대체공휴일 휴장.

prime-jennie family 데이터 자원은 다섯 갈래다. v3 의 짧은 이력 (5-22 결정론 코어 이후 30 sheet), v3 의 LLM 코어 시기 (4-18 ~ 5-22), v2 (my little jennie) 의 긴 이력 (~/backups/jennie_db_20260417_1615.sql.gz, 178M), v2 가 이미 한 번 분석해 둔 자료 (`prime-jennie/experiments/` 의 5 가설 + reports CSV), 그리고 my-prime-jennie / our-prime-jennie 의 옛날 버전.

## 2. 이번 세션 작업

### 2.1 데이터 자원 인벤토리 + v2 백업 복원

먼저 v3 Postgres 의 현재 테이블을 다 훑어서 어디에 무엇이 있는지 정리했다. 016 migration 이 legacy_* 테이블 (legacy_trade_logs / legacy_signal_logs / legacy_quant_scores 등) 을 전부 drop 했다는 것을 발견. v2 trade 결과를 분석하려면 mariadb 178M 백업 복원이 필수다.

MS-01 호스트에서 mariadb:10.11 임시 컨테이너 (`pj-v2-tmp`) 를 tmpfs 4G 로 띄워 dump 를 통째로 로드. 110 테이블 중 핵심 6 개 (trade_logs 437, signal_logs 408,941, daily_quant_scores 20,996, watchlist_histories 9,479, llm_decision_ledger 16,768, stock_news_sentiments) 확인. 분석 후 컨테이너는 `docker rm -f pj-v2-tmp` 로 제거했다. dump 만 보존, 컨테이너는 매번 일회용 패턴이 검증됐다.

### 2.2 v2 실 거래 245 건 분석

v2 의 매도 (SELL) 245 건이 평균 +2.50% / 건, 승률 64% (157승/68패/5보합), 평균 보유 2.94일, 총 실현 +3,019만원이다. 청산 사유를 보면 자동 익절 시그널 (Scale-out L1 / TRAILING_STOP / PROFIT_TARGET / RSI 과열 청산) 은 거의 100% 승률, 자동 손절 (ATR / STOP_LOSS / Dynamic) 도 -2~-6% 선에서 정상 절단됐다. 수동 매도 69 건도 평균 +2~+4% 흑자.

누적 수익 상위 종목 결: 금융주 (NH투자증권 +370만 / 신한지주 +320만 / KB금융 / 키움 / 삼성증권), 산업재 (에스엘 +734만 / 효성 +353만 / 영원무역 / 대한항공 +186만 / 포스코인터 / 현대모비스 / 한국타이어), 유틸리티 (한국전력 +681만), 통신 (SK텔레콤). 사용자가 "알파의 출처" 라고 명시한 시기의 정확한 결이다.

### 2.3 v3 LLM 시기 132 건과의 대조

같은 outcomes 테이블이지만 sheet_id 가 `bt_*` 인 백테스트 38 건과 실 매매 132 건을 분리해야 했다. 백테스트는 5-22 single-day 라 의미 없음 (모두 data_end 강제 청산). 실 매매 132 건이 평균 -2.24% / 건, 승률 27% (36승/96패), fixed_sl 67% / trailing_tp 22%. 손익비 1.14:1 은 정상이지만 승률 22% 라 expectancy 적자 구조.

적자 누적 상위 종목: 엘앤에프 -42.6% (8회 전패), HD현대일렉 -26.4% (5회 전패), 카카오뱅크 -23.8%, 아모레퍼시픽, 대한전선, 카카오, 카카오페이, NAVER, 삼성SDI, 한화시스템. 2차전지·IT 성장주·플랫폼·소비재 중심으로 v2 와는 완전히 다른 결이다. 같은 종목 (엘앤에프 / 대한전선 등) 을 반복 매매하면서 누적 손실을 키웠다는 점도 눈에 띈다.

### 2.4 v3 결정론 코어가 v2 winners 를 못 뽑는 이유

v2 누적 수익 상위 18 종목 중 12 종목이 v3 universe 에 들어와 있고 5-22 이후 점수도 매겨졌는데, 실제 promoted 된 건 HD건설기계 (2회) 와 SK텔레콤 (2회) 둘뿐이다. 나머지 10 종목 (KB금융 / 현대모비스 / NH투자 / 한국전력 / 신한지주 / 삼성증권 / 키움증권 / 대한항공 / 한국타이어 / 포스코인터) 은 점수는 있는데 screening_candidates 20 개 안에 못 들어왔다.

5-22 이후 평균 점수 비교가 결정적이다. v3 promoted 18 종목의 supply_demand 평균은 12.7, universe 평균은 9.2, v2 winners 12 종목 평균은 9.5. total 점수 차이 (47.7 vs 56.8) 의 약 35% 가 이 한 컬럼에서 발생한다. v3 가 거래대금 큰 대형주에 자동으로 끌리는 구조다.

### 2.5 supply_demand × 0.5 시뮬레이션

SQL 로 가중치 조정만 적용해서 universe 를 재정렬했다. supply_demand × 0.5 로 줄였을 때 top 25 안으로 v2 winners 가 새로 진입한 종목: 대한항공 (18 → 7), SK텔레콤 (20 → 16), 한국타이어 (17 → 20), 현대모비스 (23 → 25), HD건설기계 (28 → 27). 동시에 코웨이·LG유플러스·SK바이오팜·기업은행 같은 v3 가 안 보던 종목도 top 25 안으로 새로 올라왔다.

금융주 (신한지주·KB금융·NH투자·키움·삼성증권) 는 supply_demand 무관하게 5월 점수 자체가 낮아서 여전히 top 진입 못 함. universe 평균보다 한참 아래.

### 2.6 시기 차이 확인

금융주가 v3 에서 안 잡히는 게 점수 구조 탓인지 시기 탓인지 확인하려고 v2 era 의 daily_quant_scores 를 들여다봤다. universe 평균 비교에서 v2 시기 (2026-03-18~04-17) 가 momentum 11.0 / news 6.6, v3 시기 (5-22 이후) 가 momentum 7.6 / news 5.0. 5월 시장이 더 차분하다.

같은 v2 winners 종목의 점수 변화는 더 명확하다. 신한지주 50.3 → 45.4 (-4.9), 키움증권 48.4 → 34.2 (-14.2), 삼성증권 49.7 → 38.1 (-11.6) 으로 금융주는 다 떨어졌다. 반대로 대한항공 45.8 → 57.7 (+11.9), 현대모비스 44.5 → 55.4 (+10.9), 한국타이어 51.0 → 57.8 (+6.8) 로 자동차·항공은 오히려 더 강해졌다.

즉 v3 의 7팩터가 금융주 알파를 못 잡는 게 아니라 5월에 정말 약한 거다. 같은 점수로 v2 시기에는 신한지주가 universe 평균 위였다. 금융주를 강제로 끌어올 필요 없다.

1순위는 quant.py 의 supply_demand 손질이다. 두 갈래 중 하나를 고른다.

(a) 가장 단순한 방식은 `V2_WEIGHTS["supply_demand"]: 20 → 10` 으로 가중치만 절반. 시뮬레이션상 자동차·항공·통신·산업재 v2 winners 가 top 25 에 정상 진입하고, 반도체/IT 대형주 일부 (삼성전자/SK하이닉스/LG디스플레이/LG전자) 가 자리를 비운다. 회귀 테스트 통과 + 백테스트 비교만 통과하면 한 줄 수정으로 끝나는 안전한 안이다.

(b) 더 근본적인 방식은 `_supply_demand_score` 의 절대 금액 임계값 (외인 5e9 / 기관 5e9) 을 거래대금 증가율 기반으로 재설계. v2 winners 의 supply_demand 평균이 universe 평균과 거의 같았다는 데이터는 "거래대금 절대값 자체는 변별력이 없다" 는 강한 단서다. 이 안은 외부 데이터 확인 (외인/기관 매수의 시계열 변동) 이 필요해서 한 세션으로 안 끝난다.

(a) 부터 일주일 정도 돌려서 결과 본 뒤 (b) 로 진입하는 게 순서. 이건 이전 세션 (0003) 의 "다양성 메커니즘 폐기 — 변별력 강화로 방향" 결정의 자연 연장이다.

## 5. 중요 참고사항

이번 세션은 코드 변경이 한 줄도 없다. 분석만으로 다음 작업의 1순위를 잡았다. 메모리 한 건 추가 (`project_2026_05_25_selection_analysis.md`). v2 baseline (245건 +2.5%/건 64% 승률 +3,019만원) 과 v3 LLM 시기 baseline (-2.24%/건 27% 승률) 은 향후 점수 구조 손질 후 회귀 비교 기준선이 된다.

분석 도중 의외 발견 한 가지. outcomes 170 건 중 38 건이 sheet_id `bt_*` 백테스트라 실 매매 132 건과 섞여 있었다. 첫 쿼리에서 평균 -173% 같은 비현실적 결과가 나왔던 게 이 단위 혼동 + 백테스트 혼입 때문. 향후 outcomes 분석 시 `WHERE sheet_id NOT LIKE 'bt_%'` 분리 필수다. 그리고 pnl_pct 컬럼은 percent 단위 (5 = 5%) 이지 ratio 가 아니다.

v3 의 daily_quant_scores 가 22,152 row (3-18 ~ 5-25, 25 일치) 인데, 일별·종목별 점수 매트릭스로 5-22 이후만 가지고도 universe 전체 재정렬 시뮬레이션이 충분히 된다. 코드 수정 없이 SQL 한 줄로 가중치 시나리오 비교가 가능한 인프라가 이미 깔려 있는 셈.

v2 시기에 사용자가 직접 매수·매도한 흔적 (MANUAL_SELLALL 39건 / MANUAL_SELL 30건) 이 전부 흑자였다는 점은 별도로 의미가 있다. 시스템 자동화의 목표가 "사람의 결을 시스템에 옮긴다" 라면, 사용자의 매도 결정 시점 데이터가 진입 타이밍 신호의 후보가 될 수 있다. 다음 세션 또는 그 이후에 다뤄볼 가치가 있는 갈래.
