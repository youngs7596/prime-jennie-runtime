### 3) Publisher FK race 추적 중 발견한 2차 regression fix (`c9673f4`)

shadow candidates 기능 추가하며 `persist_screening_candidates` 가
`persist_scout_run` **보다 먼저** 호출되도록 순서가 뒤바뀜. FK 제약
(`screening_candidates.scout_run_id → scout_runs.scout_run_id`) 위반으로
**1 시간 동안 primary candidates 0건 저장**되는 regression. 증상:

- sheets_published 는 12 건 정상 (position_sheets upsert 는 별 경로)
- Scout 페이지 Candidates 카드 비어보임
- screening_candidates 테이블 최근 1h: 0 row

`persist_scout_run` 먼저 → `persist_screening_candidates` 나중으로 되돌려 해결.
smoke 재실행으로 primary_cand=12 / shadow_cand=10 복원 확인.

## 중요 참고사항

### FK 순서 주의 (이번 세션에서 배운 교훈)

`screening_candidates.scout_run_id → scout_runs(scout_run_id)` FK 가 있어
**persist_scout_run 이 반드시 persist_screening_candidates 보다 먼저** 호출되어야
한다. 순서를 바꾸면 FK violation 으로 후자가 조용히 실패 (try/except). 증상은
sheets_published 가 있는데 Candidates 카드가 비어보이는 양상.

publisher 의 position_sheets upsert 도 동일 맥락 — `update_candidate_promotion`
이 FK `promoted_to_sheet_id → position_sheets(sheet_id)` 를 치기 전에 sheet 가
DB 에 있어야 한다 (이전 세션 `0be41c0` fix).

### LLM tier 변경 시 체크리스트

Scout/Macro 등 tier 를 변경하면 아래 모두 갱신:

1. `slow_loop/app.py::_try_build_tiered_router` — primary/shadow tier 매핑
2. `slow_loop/persistence.py::_tier_model` — service → model name 반환
3. `dashboard/routers/llm_stats.py::_SERVICES` + `_FEATURE_MAP` +
   `_service_model` — UI 표시 + 집계
4. `docs/REAL_MODE_MIGRATION_CHECKLIST.md` G5 게이트 — 배포 확인
5. `.ai/sessions/session-*.md` — 전환 사유 기록

이번에 `_service_model("scout")` 누락이 LLM Stats regression 의 주원인.

### Shadow 는 primary 결정에 영향 없음

shadow 실행 실패는 전부 swallow (warning log 만). primary + shadow 가
asyncio.gather 로 병렬이라 shadow 가 느려도 전체 시간은 primary 기준.
shadow 후보는 screening_candidates 테이블 INSERT 안 됨 (FK 회피 + "비교
전용" 의미 명확). 오직 `metadata_json.shadow.candidates` 에 JSON 배열로만.
