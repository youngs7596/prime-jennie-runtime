## 1. 무엇을 만들었나

`prime_jennie_runtime/coordinator/state.py` 가 신설된 핵심. 이 안에서 KIS 잔고 (`positions` 테이블) 와 미청산 시트 (`position_sheets LEFT JOIN outcomes WHERE closed_at IS NULL`) 를 종목 단위로 합쳐 출처 셋 중 하나로 분류한다.

- `external` — KIS 잔고만 있고 v3 시트 없음. 사용자 수동 매수 또는 v2 잔존 케이스.
- `sheet` — v3 시트만 있고 KIS 잔고 없음. 분할 매수 도중이거나 reconcile 갭.
- `mixed` — 둘 다 있음. 정상 보유 경로.

`HeldPositionSummary` Pydantic 모델 (ticker, name, quantity, average_buy_price, sector_group, source, open_sheet_ids) 과 `async def get_held_positions(engine, *, ticker=None)` 비동기 함수가 공개 API. engine 미주입 또는 DB 오류는 빈 list 로 fail-open — 기존 scout context_builder 의 `_fetch_today_entries` / `_fetch_previous_outcomes` 와 동일한 패턴이다.

Scout 의 `context_builder.build()` 에서 `get_held_positions(self.engine)` 호출해 `ScoutContext.held_positions` 에 주입. 시점이 다른 fetch 들과 동일한 try/except 블록 안에 들어가 있어 State Hub 가 깨지더라도 Scout 진행 자체는 보장한다.

이번 commit 은 inject 만. quant.py, strategy/engine.py, 다른 consumer 무변경.

## 2. 머지 로직 핵심

양쪽 SQL 이 `ticker` 인자를 지원하도록 SQL 두 버전씩 준비 (`_ALL` / `_ONE`). ticker 가 None 이면 전체, 지정 시 해당 종목만. 그 후 `set(positions) | set(open_sheets)` 합집합을 사전순 정렬해 순회하면서 source 분류 + Pydantic 인스턴스 생성. quantity 는 KIS 잔고가 source-of-truth (sheet-only 면 0), average_buy_price 도 마찬가지 (sheet-only 면 None).

`name` / `sector_group` 도 KIS positions 가 source-of-truth — sheet-only 케이스에선 ticker 외에는 알 수 없으니 None. 종목명을 따로 알아야 한다면 후속 commit 에서 `stock_masters` JOIN 추가 검토.

## 7. 중요 참고사항

`ScoutContext.held_positions` 가 default empty list 라서 다음 Scout 실행에서 engine 미주입 환경 (테스트, sandbox 등) 도 그대로 동작. 운영 환경에선 engine 주입돼 있으니 자동으로 채워진다.

State Hub 의 sheet 분류 기준은 `outcomes.closed_at IS NULL` 한 줄. outcomes 행이 아예 없는 시트 (체결 직후) 도 LEFT JOIN 으로 NULL 처리돼 미청산으로 잡힌다. closed_at 채우는 곳은 fast_loop 의 exit_executor — 그 흐름이 깨지면 sheet 분류가 모두 mixed/sheet 로 부풀어 보일 수 있으니 향후 reconcile 가드 추가 후보.

`name` / `sector_group` 이 sheet-only 케이스에 None 인 한계는 후속 commit 에서 `stock_masters` JOIN 으로 채우거나 (스키마는 이미 있음), Telegram 알림 / Scout prompt 노출 단계에서 fallback 처리. 이번 단계에선 의도적으로 보류 — 활용 layer 가 정해진 다음 결정.
