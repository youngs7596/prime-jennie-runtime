# 외인 선물 수급 신호 — 출처 실측과 수집 설계 (2026-07-12)

## 계기

딴지 [889323830] "외국인 선물 포지션으로 월요일 시장을 판단해 보시라". 저자 주장 요약:

1. 7/1 까지 외인 선물 포지션은 뉴트럴하게 리셋돼 있었고, 7/2 부터가 진성 롱 축적이었다.
2. **그런데 그 일별 투자자별 집계를 믿으면 안 된다** — 장중 합성 포지션, 전매도/환매수
   혼합 청산, 그리고 **야간선물 청산은 집계에서 누락**되기 때문이다.
3. 금요일(7/10) 13:09 고점 1248.90 부근에서 순증 +3,091 을 찍고 되팔아 장 마감엔 −2,599.
   정규장에서만 약 5,690 계약 청산. 야간장에서 −4,700 계약 추가 청산(미결제 감소).
4. 결론: 외인의 진성 롱이 금요일 오후~야간에 대부분 청산됐다.

즉 이 글의 진짜 내용은 "외인 선물 순매수를 보라"가 아니라 **"외인 선물 순매수 숫자를
믿지 말라, 실제로 살아있는 포지션은 다르다"** 이다. 이 구분이 아래 설계를 결정했다.

## 실측 — 무엇을 받을 수 있고 무엇을 못 받나

MS-01 kis-gateway 컨테이너에서 실계정(openapi.koreainvestment.com, is_paper=False)으로 직접 호출.

### ❌ 투자자별(외인/기관/개인) 선물 순매수 — 수집 불가

- KIS 국내선물옵션 API 카탈로그(43개)에 **투자자별 매매동향 엔드포인트가 아예 없다**.
- 국내주식 쪽 `inquire-investor-time-by-market`(FHPTJ04030000)에 선물 시장구분을 넣어봤다:
  `FID_INPUT_ISCD` = `F` / `101` / `0001` → **rt_cd=0 인데 전 항목이 0**. (에러가 아니라
  조용한 0 이라 더 위험 — 이 API 는 현물 전용이다.) `999`/`S001` 만 현물 값이 나온다.
- KRX: 웹포털은 2025-12-27 회원제 전환으로 막혔고(재조사 금지, `reference_korean_market_data_sources`),
  KRX OpenAPI 카탈로그엔 투자자별 거래실적 서비스가 없다.

**→ 딴지 글의 이미지 3·4(일별 투자자별 매매현황)에 해당하는 데이터는 우리 스택에서 재현 불가.**
그런데 그건 저자 본인이 "믿지 말라"고 한 바로 그 데이터다.

### ✅ 미결제약정·베이시스 — 수집 가능 (KIS 선물 시세)

`GET /uapi/domestic-futureoption/v1/quotations/inquire-price`, tr_id `FHMIF10000000`,
`FID_COND_MRKT_DIV_CODE=F`.

2026-07-12(일) 실측, 정규 KOSPI200 선물 9월물 `A01609` ("F 202609"):

| 필드 | 값 | 비고 |
|---|---|---|
| `hts_otst_stpl_qty` (미결제약정) | **157,869** | 글 이미지1의 정규장 미결제와 **정확히 일치** |
| `otst_stpl_qty_icdc` (미결제 증감) | −5,320 | |
| `futs_hgpr` (당일 최고가) | **1248.90** | 글의 "13:09 당일 최고점 1248.90"과 일치 |
| `basis` / `hts_thpr` / `dprt` | 4.95 / 1201.64 / 0.74 | 베이시스·이론가·괴리율 |

즉 **저자가 실제 근거로 삼은 관측치는 전부 우리 손에 들어온다.** 위조·은폐가 불가능한
집계치(OI, 베이시스)라는 점에서 오히려 투자자별 순매수보다 신뢰도가 높다.

**종목코드 체계** (실측으로 확정): `A` + 상품(`01`=정규 KOSPI200, `05`=미니) + 연도 끝자리 +
월 2자리. 예) `A01609`=정규 2026-09월물, `A05608`=미니 2026-08월물, `A01703`=정규 2027-03월물.
결제월은 분기물(3/6/9/12)뿐. 롤오버는 "가까운 분기물 2개 중 OI 큰 쪽"으로 자동 추종
(9월물 157,869 vs 12월물 7,986).

### ❌ 과거 미결제약정 — 백필 불가

`inquire-daily-fuopchartprice`(FHKIF03020100)의 일별 배열(output2)은
`stck_bsop_date / futs_prpr / oprc / hgpr / lwpr / acml_vol / acml_tr_pbmn / mod_yn` 뿐 —
**미결제약정이 없다.** OI 는 output1 의 "오늘 스냅샷"으로만 온다.

**→ 즉시 백테스트가 불가능하다. 오늘부터 전방 적재하는 수밖에 없다.** (게이트 닫힘 그림자
측정과 같은 처지다.) 유일한 백필 우회는 KRX OpenAPI 파생 시세 서비스(ACC_OPNINT_QTY)로,
영석님 KRX 키에 해당 서비스 신청이 필요하다 — 필요해지면 그때 검토.

## 구현 (commit b459105, migration 028)

- gateway `GET /api/futures/kospi200` — 최근월물 자동 해석 + OI/베이시스/괴리율/잔존일수.
- `jobs/market_inputs.collect_futures_oi(slot)` → `futures_oi_snapshots`.
- cron 4슬롯: `preopen` 08:50 / `close` 15:50 / `night_open` 18:10 / `night_close` 익일 05:05.
  `night_close` 는 trade_date 를 하루 당겨 적재 → **같은 날짜의 `close` → `night_close`
  OI 차이가 곧 '야간 청산분'**, 글의 핵심 주장을 그대로 측정하는 필드가 된다.
- **게이트에는 연결하지 않는다.** VKOSPI·연기금 때(2026-06-24)와 같은 규율 — 예측력이
  데이터로 확인되기 전엔 매크로 입력으로 승격하지 않는다.

## 미검증 — 다음 거래일에 확인할 것

**야간 세션이 REST 스냅샷에 반영되는가.** 일요일 조회 시 OI 는 157,869(정규장 마감값)로,
글이 말한 야간 전광판 값 157,244 가 아니다. KRX 야간 파생 체결이 익영업일 거래로 집계되기
때문일 수도, REST 가 정규장 값만 주기 때문일 수도 있다. **추측하지 말고 네 슬롯을 다 찍어
데이터로 판정한다** — night_open/night_close 가 close 와 다른 값을 주면 반영되는 것이고,
똑같으면 반영되지 않는 것이다. 후자면 야간 OI 는 웹소켓(`H0MFCNT0`, KRX야간선물 실시간체결 —
`hts_otst_stpl_qty`·`otst_stpl_qty_icdc` 포함)으로만 잡을 수 있고, 우리 streamer 인프라를
재사용해 붙이면 된다.

## 민지 리뷰 반영 (2026-07-12, 승인 + 보완 3건)

### 1. 롤오버 오염 — 코드로 수정 (commit 후속, migration 029)

만기 주간엔 미결제약정이 근월물에서 차월물로 **이전**되면서 근월 OI 가 급감한다. 근월물
하나만 찍으면 이 이전이 '청산'으로 오독되고, 판정 표본 60거래일 안에 만기가 최소 한 번
끼므로 분석 결과 자체가 오염된다. → **근월·차월 두 계약을 모두 적재**하도록 고쳤다
(`is_front`, `last_trade_date` 컬럼 추가). 실측 확인: 근월 A01609 157,869 + 차월 A01612
7,986 = 합산 165,855.

**판정 시 지켜야 할 규칙:**
- OI 델타는 **같은 (trade_date, slot) 의 두 계약 합산** 으로 계산한다 → 롤오버가 중화된다.
- 근월물 단독 델타를 쓸 거면 `last_trade_date` 로 만기 주간을 식별해 그 구간을 제외한다.
- 계약별 행이 남아 있으므로 이전량(근월 −N ↔ 차월 +N)도 따로 관찰 가능하다.

### 2. 캘린더 엣지 — 동작 명시

- 슬롯 크론은 **거래일 캘린더를 탄다.** preopen/close/night_open 은 평일 크론(1-5) + 핸들러의
  `is_trading_day_via_gateway` 가드(KIS chk-holiday) → 휴장일엔 실행되지 않는다.
  night_close 는 화~토 크론(2-6) + DB 가드(그 trade_date 에 `close` 행이 있나) → 금요일 밤
  세션이 토요일 새벽에 끝나는 구조를 정확히 태운다.
- **휴장일엔 행을 아예 안 남긴다.** 전일값 복사(forward-fill) 없음, NULL 행 없음 —
  결측은 '행 부재'로만 나타난다. paper outcomes NULL 유형의 재발 여지를 원천 차단.
- **남은 함정 하나(분석에서 처리):** 휴장일 *전날* 밤엔 KRX 야간장이 안 열릴 수 있다. 그러면
  night_close 행의 OI 가 close 와 같아져 '야간 청산 0' 처럼 보인다. 이건 **거래량(`volume`)이
  close 와 동일한지**로 구분한다 — 야간 거래가 실제로 반영됐다면 누적 거래량이 늘어나야 한다.
  OI 델타만 보지 말고 volume 델타를 같이 볼 것.

### 3. KRX 백필 커버리지 — 기대치 정정

KRX OpenAPI 파생 시세로 백필되는 건 **일별 마감 OI** 다. 따라서
- 판정 ②(베이시스)·③(4분면) → 백필로 **즉시 백테스트 가능**.
- 판정 ①(야간 청산분) → 마감↔야간 세션 구분이 필요하므로, KRX 과거 데이터에 야간시장 OI 가
  **별도로 제공되는지에 달렸다.** 없으면 ① 은 어차피 60거래일 전방 적재를 기다려야 한다.

"백필하면 3개월 안 기다려도 된다"는 ②③ 에만 성립하는 문장이다.

## 판정 계획 (약 3개월 뒤, 표본 60거래일 내외)

승격 논의는 아래를 다 채운 뒤에만 연다. 미리 기준을 적어두지 않으면 "쌓아만 두고 미루는
데이터"가 된다.

1. `night_unwind` = `close.OI − night_close.OI` (양수 = 야간 청산). 이 값과 익일 KOSPI
   수익률의 상관·분위수별 평균.
2. 베이시스(`basis`, `dprt` 괴리율)와 익일/T+3 수익률.
3. OI 증감 방향 × 가격 방향 4분면 (신규 롱 / 숏커버 / 신규 숏 / 롱청산) 별 익일 수익률.
4. 승격 기준: 분위수 단조성 + 상하위 분위 수익률 차이가 잡음 범위 밖. 못 넘으면 폐기하고
   수집만 유지하거나 접는다.
