## 2. 동작 그림

**시나리오 A — 조건부 매도 (v1 범위).**
"서진시스템이 양전하거나 -1% 미만으로 손실이 줄어들면 매도해줘"
→ 봇: "서진시스템(178320) 1주 · 손익률 -1% 이상 회복 시 전량 시장가 매도. 맞습니까?
   <code>확인</code> 으로 등록" (매입가 80,800원 기준 79,992원 이상에서 발동을 함께 표기)
→ 사용자: "확인"
→ 등록 = KIS 잔고에서 매입가·수량을 읽어 관리용 시트 발행 + tracker 등록 + threshold
   exit 룰 부착. 이후 fast-loop 이 tick 마다 평가, 발동 시 시장가 매도 + 텔레그램 통지.

**시나리오 B — 추천 수락 매수 (v1 범위 밖, 매도 경로 검증 후).**
scout 가 시트를 발행하면 텔레그램으로 추천 요약 발송 → "1번 사줘" → 해석 echo →
확인 → 매수. PAUSE 가 수동 매수를 막는 현 구조와의 정책 충돌 (승인 매수에 PAUSE
예외를 둘 것인가) 은 B 설계 때 결정한다.

## 3. 구현 변경 4곳 — 작업 순서대로

1. **threshold exit 룰 추가 (공유 스펙).** 현 9종 exit 룰에 "손익률이 음수 임계 위로
   회복하면 매도" 를 표현할 룰이 없다 (fixed_tp 는 pct>0 강제, schema.py:55).
   음수~양수 임계를 받는 룰 1종 추가. `position_sheet/schema.py` 는 stop-the-world
   공유 스펙이므로 fast_loop exit_evaluator + paper 시뮬레이터 (jobs/paper_outcomes.py
   는 evaluate 재사용이라 자동 반영, 테스트로 확인) + POSITION_SHEET_SPEC.md 를
   같은 commit 에서 갱신.

2. **보유 편입 경로.** 시트 만료로 tracker 밖에 있는 실보유 (서진시스템 등) 를
   KIS 잔고 기반으로 관리용 시트 발행 + tracker 등록 + ticker 구독. 5-21 KODEX200·
   두산밥캣 수동 편입 전례의 명령화. 편입 시트의 hold_days placeholder 는 측정 제외
   필터 (MAX_MEASURABLE_HOLD_BDAYS=60 초과) 에 걸리게 해 paper 측정 오염 차단.

3. **intent 층 v2.** 19개 명령 분류기 → 구조화 추출기. 닫힌 조건 어휘 (시작은
   손익률 임계·가격 임계, 이상/이하 두 방향), 확인 대기 상태는 Redis TTL (10분),
   실패·어휘 밖 입력은 무응답 대신 "이해하지 못했습니다 + 가능한 형식 안내" 회신.
   기존 "매매성 명령은 LLM 추출 시 무조건 차단" 설계 (llm_intent.py docstring) 는
   "확인 단계 없이는 실행 금지" 로 교체.

4. **운영 상태 전환 (코드 아닌 절차).** stop=1 → `/resume 확인` → `/pause`.
   PAUSE 가 정확히 "진입 차단 + 청산 허용" 이므로 v1 (조건부 매도) 의 목표 운영
   상태다. slow-loop 시트는 paper publisher 가 emit_stream=False 라 fast-loop 매수
   경로에 애초에 닿지 않는다 — 자동 진입 부활 없음.

## 4. 안전 원칙

- 매매성 등록은 예외 없이 해석 echo + "확인" 2단계. 즉시 실행 없음.
- 조건 어휘는 닫힌 집합으로 시작, 어휘 밖은 등록 거부 + 안내. 확장은 운영 데이터 본 뒤.
- 등록된 조건부 주문의 조회·취소 명령을 같은 슬라이스에서 제공 (가시성 없는 standing
  order 는 그 자체로 위험).
- 발동·실패 모두 텔레그램 통지 (조용한 실패 금지 — status=success 학습).
