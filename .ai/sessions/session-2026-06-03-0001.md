## 1. KIS 경고 반복 사건 — 진단 여정과 결론

어제 (6-2) 텔레그램으로 KIS Gateway 경고와 해제가 하루종일 반복됐다. 원인을 세 단계에
걸쳐 좁혀갔고, 앞의 두 가설은 틀렸다.

**1차 가설 (기각): 계좌가 KIS 측 민감 상태다.** 분봉 수집이 초당 20건으로 한도를 위반해온
누적 때문에 계좌가 제재 상태라고 봤다. 영석님이 "스택을 전부 내리고 직접 호출해보라" 고
제안했고, 그 결과 계좌는 완전히 정상이었다 (시세 초당 17.6건 연속 30번 통과). 이 과정에서
3건짜리 표본으로 "통과" 를 결론 내렸던 것도 문제였다 — 표본이 작으면 우연히 통과한다.

**2차 가설 (기각): WebSocket 연결이 간섭한다.** gateway 만 단독 재시작해 WebSocket 없는
상태를 만들어도 충돌이 계속됐다.

**최종 결론: 원장 동시 조회 충돌.** KIS 의 원장 (잔고·주문 계열) 은 같은 계좌에 대한 조회가
시간상 겹치면 양쪽 모두 거부한다 (오류 메시지가 시세 한도와 다르다 — "원장에서 허용 가능한
초당 거래건수 초과"). 충돌원은 둘이었다.

- 내부: monitor (30초) · 기타 서비스들이 각자 잔고를 물으면서 서로 충돌
- 외부: **영석님의 KIS 모바일앱 (MTS) 사용** (본인 확인됨). "한번 발생하면 하루종일" 의
  정체는 되먹임 고리 — 경고 알림을 받으면 앱을 열어 확인하고, 그게 더 많은 충돌과 알림을
  만든다.

추가로, 분봉 수집의 시세 한도 (초당 ~18-20건) 위반은 별개의 진짜 문제였다 (1차 가설의
근거였던 현상 자체는 실재).

**해결 (4겹 방어, 전부 배포·검증 완료):**

1. 전역 시세 limiter — 모든 KIS 호출 (재시도 포함) 이 합산 한도 (10/sec) 를 거침
2. gateway 잔고 캐싱 (5초) + 단일 비행 — 동시 요청은 한 번의 KIS 호출을 공유
3. EGW00201 재시도 1회 → 2회 — 외부 (MTS) 충돌 흡수
4. **잔고 단일 발행/다중 구독 구조** (영석님 제안) — 시세 tick stream 과 같은 철학.
   monitor 가 유일한 잔고 폴러로 Redis 에 스냅샷을 발행하고, 조회 용도의 모든 소비자
   (dashboard / telegram / 브리핑 / 자산 스냅샷) 는 스냅샷을 구독. ground truth 검증
   (reconcile/sync) 과 매매 직전 sizing 만 HTTP 직접. 새 모듈: `infra/balance_snapshot.py`

배포 후 실측: KIS 로 가는 잔고 조회가 monitor 1곳으로 고정됐고, 30분간 충돌 0 · monitor
실패 0 · 경고 0. **6-4 (목) 거래일 하루 동안 경고가 한 건도 안 오면 이 사건은 종결이다.**

같이 발견해 수리한 결함: **휴장일 가드가 도입 (5-25) 이후 처음부터 무력했다.** gateway 의
개장 판정이 KIS 휴장일 조회를 참조하지 않고 "평일=거래일" 가정만 썼기 때문. 연결을 완성했고
오늘 휴장일에 분봉 수집·scout 가 처음으로 정상 skip 되는 것을 확인했다.

## 2. paper 모드 계획 완주 (5-29 세션의 일감)

- **P2.6 분봉·틱 수집 교정**: 6주 묵은 옛 명단 (4-17 동결) 대신 측정 윈도우가 열려있는
  시트의 종목을 수집·구독. 운영 검증 완료 (틱 구독이 29 → 24종목으로 새 구성 교체)
- **P2.7 reversal-guard paper 완화**: paper 모드 (STOP) 에서는 latch 로 게이트를 닫지 않고
  "실거래였으면 closed 였음" 메타만 기록 — latch 의 alpha 영향을 나중에 정량 측정
- **P3 측정 simulator v1**: 분봉이 충분한 날은 분당 1-tick + RSI 로 시뮬 (과열 청산 룰이
  처음으로 깨어남), 부족한 날은 일봉 fallback. 부분 청산 가중 평균 반영
- **P4 벤치마크 API**: 시트별 측정 결과 vs 같은 기간 KODEX200 수익률 (알파) 를 주는
  dashboard API 신설. control-ui 페이지는 미착수 (별도 repo)
- **설계 문서 §1.1**: 실계좌 동결 상태 명시 (5-29 분리 보류 결정의 거버넌스 기록)
- **paper 측정 버그 수리**: 윈도우가 아직 안 닫힌 시트에 영구 도장이 찍혀 재측정이 안 되는
  결함. 갇혀 있던 33건을 풀었고, 코드가 더 이상 그런 도장을 만들지 않는다

## 3. 첫 측정 데이터 분석

측정 1,086건을 분석했다 (`.ai/analyses/2026-06-03-first-paper-outcomes-analysis.md`).
99%가 폐기된 LLM 시기 (4-19~5-21) 시트라 현 전략 평가는 불가능하고, 대신 두 가지를 확정:

- LLM 시기는 시장 대비 **알파 -6.67%p** (시장이 +4.5% 오르는 동안 -2.2% 손실, 지수를 이긴
  비율 11.6%). 실거래 기록과 일치해 simulator 신뢰성도 교차 검증됨
- 손익 비대칭: 손절 평균 -7.2% (갭하락이 손절선 관통) vs 익절 평균 +2.0%

결정론 코어 (5-22 이후) 는 표본이 9건뿐이라 아직 결론 불가. 측정이 매일 쌓이므로
6월 중순 (표본 30건 이상) 에 첫 비교 분석이 가능하다.
