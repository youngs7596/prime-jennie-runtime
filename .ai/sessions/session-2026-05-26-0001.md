### 2.2 두 갈래 원인 발견

**갈래 1 — 코스닥 미취급 정책이 깨졌다.**

`stock_masters.market` 컬럼이 KOSDAQ 종목 다수에서 'KOSPI' 로 오라벨됨. 서진
시스템·동진쎄미켐·주성엔지니어링·산일전기 다 KOSDAQ 인데 KOSPI 로 들어가 있다.
거기다 `slow_loop/scout/feeders/real.py:71` 의 `RealUniverseFeeder` SQL 에 market
필터 자체가 없다. `security_type='STOCK'` 필터만 있고 KOSPI/KOSDAQ 구분 없이
시총 상위로 뽑는다.

진짜 흐름은 5-22 ETF/ETN backfill 사고 때 시작됐다. 그때 stock_masters 에
KOSDAQ 1678 종목이 신규 INSERT 됐고, 같은 날 글로벌 메모리에 "이제 KOSDAQ
대형주가 universe top-200 에 일부 들어올 수 있다" 라고 기록됐는데, universe
SQL 에 KOSPI 필터 박는 후속 작업이 안 따라왔다. 4일 뒤 5-26 첫 cycle 에 사고로
터진 것.

시스템 정책은 v2 시절부터 KOSPI 만 취급. 글로벌 메모리 `trading-domain.md` 의
"Universe 종목 분류" 섹션에 5-26 후속 학습으로 박아 뒀다. 로컬 메모리도 새 항목
[[no-kosdaq-policy]] 추가.

**갈래 2 — fundamentals 데이터 비대칭. 더 큰 결함이다.**

서진시스템 quality 18 / value 16.5 가 어떻게 만점에 가까운지 raw 데이터 확인.
trail PER **-10.07** (적자), trail ROE 0.36 인 적자기업인데 forward 컨센서스가
forward_per **9.26** / forward_roe **23.65** 로 매우 강하게 박혀 있다. 분석가들이
turnaround + 큰 폭 성장 시나리오를 추정에 박은 형태. `quant.py` 의 `_quality_score`
와 `_value_score` 는 forward 우선 로직이라 trail 의 적자 신호가 완전히 가려진다.

반대로 SK하이닉스/삼성전자/LG디스플레이 같은 KOSPI 대형주는 quality 점수가
ROE 한 컬럼만으로 10점 천장. 왜? `stock_fundamentals` JOIN 쿼리에서 PER/PBR
null 로 나옴. 처음엔 "데이터가 비어있다" 로 봤는데, 종목별 trade_date 별 행을 펴
보니 4-15 행에는 PER 11.04 / PBR 3.73 / ROE 44.15 모두 채워져 있다. 다만 5-01
trade_date 에 ROE-only row 가 더 최신으로 들어가 있고 그 행은 PER/PBR null.

진짜 결함은 `slow_loop/scout/enrichment.py:357` 의 SQL 패턴.
`DISTINCT ON (stock_code) ORDER BY trade_date DESC` 가 종목별 최신 한 행만 가져
온다. `collect_naver_roe` (매월 1일) 가 새 trade_date row 를 만들면서 PER/PBR
칸을 null 로 두는데, 이 행이 분기 fundamentals 행보다 최신이라 쿼리가 null
PER/PBR 을 받아온다. **데이터는 DB 에 있는데 SQL 한 줄 때문에 가려진다.**
v2 시절부터 반복된 PER/PBR 부재 결함이 v3 enrichment 포팅 때 SQL 패턴까지 그대로
옮겨와서 재발한 형태.

부수 결함도 발견. FNGUIDE 크롤러가 forward_roe 를 다수 종목에서 동일값 **8.83**
으로 박는다. 5-25 stock_consensus 에서 SK하이닉스/삼성전자/LG디스플레이/SK/
산일전기/LG전자/LS 7종이 전부 8.83. 동진쎄미켐 13.12, 주성엔지니어링 20.28,
서진시스템 23.65 는 NAVER fallback 으로 정상. FNGUIDE 페이지 셀을 잘못 긁어옴.

`collect_quarterly_financials` cron 도 문제. 분기 1회 (4·7·10·1월 15일) 라
PER/PBR 이 항상 1.5~3 달 묵은 값. 마지막 success 4-15, 다음 7-15. 월 1회
이상으로 늘리는 게 합리적.

`analyst_count` 가 전 종목 null 이라 컨센서스 신뢰도조차 못 본다.
