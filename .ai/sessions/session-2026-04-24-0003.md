## 중요 참고사항

### v3 백테스트 구조의 핵심 원칙

**fast_loop.exit_evaluator 재사용 = 단일 소스 오브 트루스.** exit rule 파라미터
조정 / 신규 rule 추가 시 runner 는 건드릴 필요 없음. evaluator 만 고치면
production 과 backtest 가 동시에 반영됨. v2 처럼 SimulatedPortfolio 에 룰을
또 구현하면 두 경로가 생겨서 drift — 이건 meta 자가진화의 가장 큰 리스크
중 하나였음.

### 일봉 tick 분해의 pessimistic 가정

하루를 O → H → L → C 순서로 4 tick 을 emit. 실제 분봉 순서는 알 수 없으므로
"고점 activate 후 저점 trigger 가 같은 날 가능" 하다는 가정. 이건 의도적
보수 (over-count exits). 분봉 데이터가 있으면 별도 runner 작성 가능하지만
v1 은 일봉만.

### death_cross 는 close tick 에서만

evaluator 의 `death_cross_checked_at` 가 하루 1회 평가로 dedup. open tick 에
오늘 close 를 노출하면 "아직 장이 안 닫혔는데 오늘 close 로 판정" 하는 causality
위반이 됨. runner 는 `closes_for_eval = closes_today if t.is_close else None`
로 처리.

### 로컬 vs MS-01

- 로컬 WSL postgres (port 5432) — 스키마만. unit test 가능, driver 실측 불가
- MS-01 — 실 데이터. driver 는 `docker compose exec` 로 컨테이너 안에서 돌려야
  DNS (kis-gateway, vllm 등) 가 풀림. backtest_replay 는 DB 만 쓰므로 job-worker
  컨테이너 안에서 실행 권장

### SectorGroup 의 새 위치

`prime_jennie_runtime.jobs.sector_taxonomy.SectorGroup`. 과거 경로
(`backtest.domain.SectorGroup`) 는 사라짐. 새 import 추가 시 주의.

### v2 엔진 폐기 근거

- `backtest/portfolio.py` (306 LOC) 의 `SimulatedPortfolio.execute_sell` 은
  사실상 `fast_loop.exit_evaluator.evaluate()` 와 같은 일을 함 (룰 순회 + 상태
  관리). 두 경로 유지는 유지보수 부담 + drift 위험
- `backtest/models.py` (236 LOC) 의 `SimPosition.scale_out_level` /
  `profit_floor_active` 같은 상태 필드는 v3 `PositionState` (fast_loop/domain.py)
  에 `scale_out_executed: set[int]` / `profit_floor_active: bool` 로 이미 존재
- `backtest/domain.py` 의 `MarketRegime` 5-level enum / `TradeTier` / `SignalType`
  / `SellReason` 은 v3 스키마 어디에도 없음 (v3 는 binary gate + size_multiplier)
