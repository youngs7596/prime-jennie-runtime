### reconcile_state_kis 의 silent drift

ticker set 만 비교하는 알고리즘은 양쪽 quantity 가 어긋나도 한쪽이 ticker 자체를 가질 때 모른다. v3 sell 로 v3 측 ticker 가 사라질 때 비로소 노출 — **시간 지연 drift 검출**. 수량 비교 추가 또는 alert payload 에 KIS 측 quantity 명시 가치.

### one-shot sync 의 안전성

fast_loop 가 이미 가동 중일 때 redis state 만 추가하면 in-memory tracker 변화 없음 (`load_from_redis()` 는 부팅 시만). 다음 fast_loop restart 시 stale state (exit_rules_raw 빈 list) 처리 path 확인이 별개 task — boot-time sync 코드 변경 시 함께 검토.

### KIS balance fetch 의 graceful fallback
