# 세션 2026-10-09-0003 — 작업 PC 유선랜 장애 추적, 무선으로 전환

## 먼저 알아둘 것

이 세션은 리포 코드를 **전혀 건드리지 않았다.** 매매 시스템의 코드·설정·DB·컨테이너 모두 변경 없고, 커밋도 없다. 작업 PC(윈도우, YOUNGS7511PRO)의 네트워크 문제만 다뤘다. 코드 작업을 이어받으러 왔다면 바로 이전 세션(`session-2026-10-09-0002.md`)을 보면 된다.

MS-01 의 매매 스택은 세션 내내 정상 가동했다 (가동 65일, 부하 0.26).

## 무슨 문제였나

작업 PC 의 유선랜이 1 Gbps 로 붙어 있다가 간혹 100 Mbps 로 떨어졌다. 사용자는 원인과 고정 방법을 물었다.

## 어떻게 추적했나

처음에는 절전 기능을 의심했다. 어댑터 설정을 보니 절전형 이더넷, 에너지 효율적인 이더넷, Gigabit Lite, Power Saving Mode 가 전부 켜져 있었고 빠른 시작도 켜져 있었다. 이것들을 다 끄고, 링크 속도가 변할 때마다 기록하는 로거를 윈도우 예약 작업으로 심었다.

약 1시간 20분 뒤 사용자가 게임 중에 튕겼고 유선이 100 Mbps 가 됐다. 로거가 전 과정을 잡았다.

```
21:16:02   Up   1000 Mbps   (정상)
21:30:03   Disconnected  0 bps   ← 링크 완전히 죽음
           약 1분 암전
21:31:02   Up    100 Mbps   ← 복귀하면서 100M 로 협상
```

게임이 랜을 끊은 게 아니라 **랜이 죽어서 게임이 끊긴 것**이다. 순서가 반대였다.

범위를 좁힌 근거는 세 가지다. 같은 시각 **무선은 전혀 안 끊겼다** (윈도우 무선 로그가 비어 있음) — 공유기는 살아 있었으니 유선 경로만의 문제다. 드라이버 오류 기록도 없다. 그리고 **케이블을 전혀 건드리지 않고 어댑터만 재시작했더니 즉시 1 Gbps 로 복귀**했다. 네 쌍 모두 기가비트를 실어낼 수 있다는 뜻이라 완전 단선은 아니다.

절전 기능을 다 끈 뒤에도 재발했으므로 소프트웨어 원인은 배제됐다. 남은 결론은 **간헐적 접점 불량**이다. 한 번 100M 로 협상되면 자동협상이 스스로 다시 올려보지 않으므로 계속 100M 에 머문다.

사용자 진술로 범인이 확인됐다. 깔려 있던 건 **4~5m 납작(flat) Cat6 케이블, 2~3년 사용**. 직선거리는 2~3m 인데 미관상 돌려서 깔아 길이가 늘었다. 납작 케이블은 선 쌍을 리본처럼 나란히 눕혀 꼬임의 간섭 제거 효과가 약하고, 도체도 28~30 AWG 로 얇다. 값싼 제품은 구리 도금 알루미늄을 쓰는데 이건 꺾인 자리에서 도체가 피로 파단된다. 길이는 무관하다 — 4~5m 는 기가비트 한계인 100m 에 한참 못 미친다.

## 왜 무선으로 갔나

사용자가 유선 케이블을 뽑고 무선만 쓰기로 했다. 분봉 단위로 돌아가는 시스템에서 1ms 와 5ms 는 차이가 없고, 중요한 건 1분간 끊기지 않는 것이라는 판단이었다. 측정값이 그 판단을 받쳐준다.

| 측정 | 손실 | 평균 | 최대 |
|---|---|---|---|
| 공유기 | 0% | 3.7ms | 40ms |
| MS-01 | 0% | 4.7ms | 45ms |
| 인터넷 | 0% | 9.6ms | 53ms |

처리량은 SSH 스트림으로 **558 Mbps 이상**. 암호 방식만 하드웨어 가속되는 것으로 바꿔 343→558 Mbps 가 됐으니 이 측정의 병목은 무선이 아니라 SSH 쪽이고 무선 실제 상한은 더 높다. MS-01 에 iperf3 가 없는데 운영 서버라 설치하지 않았다.

## 현재 상태

작업 PC 는 **무선만 쓴다.** 유선 어댑터(`이더넷 2`, Realtek RTL8126 5GbE)는 케이블을 뽑은 뒤 **Disabled 로 꺼놨다.**

무선은 보드 기본 안테나(상어 지느러미 모양, 금색 커넥터 2개) 둘 다 연결, AP 와 3m 가시선, RSSI -27dBm, 5GHz 채널 36, 802.11ax, 링크 2402 Mbps. 2402 Mbps 가 나오는 것 자체가 안테나 두 줄기 모두 동작한다는 증거다 (한 줄기면 1201 Mbps).

인터넷·DNS·MS-01 SSH 전부 확인했다.

## 망 구성 (알아두면 좋은 것)

U+ 모뎀 → U+ 공유기 → 그 아래 **메쉬**. 서브넷은 192.168.31.0/24, 게이트웨이 192.168.31.1. PC 무선이 `.250`, MS-01 유선이 `.195` 무선이 `.220`. MS-01 의 유선은 1 Gbps.

채널 36 에 AP 6개가 잡히는데 **전부 사용자 본인 장비**다. 노드 3대 × 각 2개(일반 `U+NetDC60` + 숨겨진 백홀). `50:xx` 와 `5a:xx` 는 같은 무선 칩이 만든 두 번째 가상 AP다.

PC 는 **최상위 노드에 직접 붙어 있다** (접속 BSSID `50:4f:3b:01:71:83`, 게이트웨이 MAC `50:4f:3b:01:71:80` — 같은 장비). 노드 간 무선 중계를 거치지 않으니 메쉬에서 가장 좋은 위치다.

남은 비용은 다른 노드 2대의 무선 백홀이 같은 채널 36 의 airtime 을 나눠 쓰는 것이고, 이게 40~53ms 스파이크의 원인이다. 해법은 노드 유선 백홀이나 160MHz→80MHz 로 낮춰 클라이언트와 백홀을 분리하는 것인데, **사용자가 "대동소이할 것 같다"며 하지 않기로 했다. 다시 제안하지 말 것.**

채널을 36 에서 149 로 옮기는 건 효과 없다. 메쉬는 노드가 같은 채널을 함께 쓰고 같이 움직이므로 내부 경쟁이 따라온다.

## 덤으로 정리된 것

이전에 원인을 못 찾고 보류했던 PC↔MS-01 지연 문제가 사실상 정리됐다. 유선일 때 PC 에서 MS-01 까지만 ICMP 평균 25.8ms·최대 119ms, TCP 평균 6.85ms·최대 104ms 가 나왔다. 각 기기에서 공유기까지는 완벽했고(PC 1.0ms 편차 0, MS-01 0.53ms) MS-01 부하·NIC·ARP·라우팅을 전부 배제했는데도 원인을 못 찾았다.

무선으로 전환한 뒤 같은 구간이 **평균 4.7ms** 로 나온다. 그 지연의 상당 부분이 접점 불량이던 유선 경로 탓이었을 가능성이 크다. 단정할 근거는 없지만 그 경로를 더 안 쓰므로 어느 쪽이든 끝난 문제다.

## 다음 단계

매매 시스템 쪽 과제는 이 세션에서 손대지 않았다. 직전 세션에서 넘어온 것들이 그대로 남아 있고, 그중 **outcomes 테이블이 운영에서 적재되지 않는 문제**가 결정론 성과 검증의 1순위 차단요인이다.

네트워크 쪽에 남은 건 선택 사항 하나뿐이다. 유선을 되살리고 싶으면 **둥근 몰드 완제품, 순동 100%, 24 AWG, Cat5e 또는 Cat6, 5m** 짜리를 사서 꽂으면 된다. 납작·구리도금알루미늄·자가 크림핑은 피한다. Cat6a 나 Cat7 은 과사양이고 뻣뻣해 배선만 어려워진다. 미관은 케이블을 얇게 하지 말고 걸레받이용 접착 클립으로 해결하는 쪽이 낫다.

## 중요 참고사항

**유선 어댑터가 Disabled 상태다. 케이블만 꽂아도 안 된다.** 관리자 권한으로 아래를 실행해서 먼저 켜야 한다. (세션 중간에 "다시 꽂으면 자동으로 유선이 우선 경로가 된다"고 말한 적이 있는데, 그건 어댑터를 끄기 전 이야기다.)

```powershell
Enable-NetAdapter -Name "이더넷 2"
```

**링크 속도 로거가 상주 중이다.** 예약 작업 `NIC Link Speed Watch` (SYSTEM 권한, 부팅 시 + 1분 간격), 스크립트 `C:\ProgramData\nic-monitor\nic-watch.ps1`, 로그 `C:\ProgramData\nic-monitor\linkspeed.csv`. 속도나 상태가 변할 때만 행을 추가하고 1시간마다 heartbeat 를 남긴다. CSV 의 `PROBE-FAKE` 행 하나는 설치 검증용 가짜 데이터다. 유선을 되살린 뒤 또 100M 가 찍히면 새 케이블도 아니라는 뜻이고, 그러면 공유기 포트나 보드 포트를 의심하면 된다.

유선 어댑터에 적용해둔 설정은 그대로 남아 있다. 절전형 이더넷·에너지 효율적인 이더넷·Gigabit Lite·Power Saving Mode 전부 끔, `PnPCapabilities = 24`(장치 절전과 WOL 끔), `HiberbootEnabled = 0`(빠른 시작 끔). 속도는 자동 교섭을 유지했다 — 1G 로 강제하면 케이블이 부실할 때 링크가 아예 안 잡히는 위험이 있어서다.

이 세션의 상세 내역은 로컬 메모리 `environment_pc_nic_linkspeed.md` 에도 정리해뒀다. 작업 PC 한 대에 국한된 하드웨어 이야기라 여러 머신에서 공유하는 글로벌 메모리로는 올리지 않았다.
