## 1. 정책 결정 — PAUSE 와 승인 매수

시나리오 B 의 선결 문제였던 "PAUSE 가 수동 매수를 막는 구조와의 충돌" 을
영석님이 결정. 선택지 넷 (확인된 승인 매수만 통과 / 수동 매수 전부 통과 /
새 운영 상태 / 매번 resume 후 매수) 중 **첫째**.

- **PAUSE 의 뜻이 바뀌었다: "사람이 2단계 확인으로 승인하지 않은 진입은 전부
  차단".** 청산은 계속 허용, STOP 은 여전히 모든 매매 차단.
- 새 명령 종류 approved_buy 만 PAUSE 를 통과한다. 확인 없는 기존 /buy 는
  계속 막힌다 (PAUSE 상시 운영에서 사실상 닫힌 문).
- 자동 진입 차단 (수량 계산기의 운영 상태 검사 + paper publisher 의 stream
  미발행) 은 손대지 않았다.
- 설계: `.ai/designs/2026-06-12-scenario-b-approved-buy.md`

## 2. 구현 (commit `91236b2`)

- **추천 발송** — slow-loop 가 시트를 DB 영속한 직후 텔레그램으로 번호 붙은
  추천 요약 발송 (종목명·전략·확신도·유효시각). 번호↔시트 매핑은 Redis
  `v3:reco:{KST날짜}` 에 당일 TTL, 같은 날 재실행이면 번호가 이어진다.
  STOP 중에는 발송하지 않는다 (수락해도 차단이라 소음만).
- **/accept 번호** — 해석 echo (시장가 기준 수량·금액·청산 룰) 와 "확인" 의
  2단계. **echo 시점에 계산된 수량이 Redis 에 10분 보존되어 확인 시 그 숫자
  그대로 발행** — 확인 시점 재계산 없음. 실행은 평일 09:00~15:20 만, 일일
  수동매매 한도 적용. 자연어 "1번 사줘" 는 echo 까지 통역 (확인은 직접 친
  슬래시만 — 기존 NL 정책 그대로).
- **집행** — fast-loop 의 control consumer 가 approved_buy 를 받아 자동
  진입과 같은 경로 (EntryExecutor: 주문, 체결 확인, 부분 체결 잔량 취소,
  tracker 등록, 기록, 통지) 로 집행. 시트의 청산 룰이 체결 즉시 보호 시작.
  시트의 진입 형식이 지정가라도 **시장가로 강제** — 사용자가 확인한 echo 가
  시장가 기준이므로. 만료·중복 보유·시트 불일치는 거부 + 텔레그램 통지.
- 문서: docs/CONTROL_STATE_KEYS.md 의 PAUSE 행 갱신, /help, NL 어휘.
- 전체 테스트 1,568 통과 (신규 20). 변경 파일 린트 깨끗.

## 5. 중요 참고사항

- **PAUSE 의미가 6-12 부로 바뀌었다** — 옛 문서나 기억의 "진입만 차단" 은
  "무확인 진입 차단" 으로 읽어야 한다. approved_buy 는 통과한다.
- /accept 의 확정 수량은 echo 시점 시세 기준이다. 확인까지 시세가 움직이면
  금액은 달라질 수 있지만 수량은 변하지 않는다 (사용자가 본 숫자가 계약).
- 수량 계산은 자동 진입과 같은 식 (총자산×비중, 시트 캡, 현금 클램프) 에서
  intraday throttle 배수만 뺐다 — 수락 시점에 사람이 직접 판단하므로.
- 추천 번호 매핑이 없으면 (/accept 가 "추천이 없습니다") slow-loop 가 그날
  시트를 발행하지 않았거나 STOP 중이었던 것.
- 휴장일은 /accept 의 평일·시간 검사가 못 거른다 — KIS 주문 거부와 실패
  통지가 잡는다 (v1 단순화, 설계에 명시).
- ruff 저장소 전체 check 는 여전히 main 부터 깨져 있음 (airflow.py 등,
  이번 변경 무관).
