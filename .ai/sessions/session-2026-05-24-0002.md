## 2. 이번 세션 작업

### 2.1 eGPU 부하 점검 + 호스트 nvidia 드라이버 mismatch

News Agent shadow 의 GPU 영향을 정량으로 봤다. shadow_agent.py 가 처리 이벤트마다 vLLM Qwen3 를 한 번 더 부르도록 되어 있어 같은 뉴스당 LLM 호출이 1 회에서 2 회로 늘었다. 다만 GPU 자체엔 여유가 있었다. 메모리 22.15 / 24 GiB 는 EXAONE FP8 모델 + KV cache 의 정상 적재량, 전력은 추론 burst 198W / idle 31W 로 안정. vLLM 큐 적체 0 건. 5-29 Phase 1 검증 끝나면 shadow → enforce 정리 흐름이 자연 통과 예정이라 추가 조치 불필요.

같은 점검에서 별도 운영 위험이 드러났다. 호스트의 nvidia-smi 가 "Driver/library version mismatch" 로 실패하고 있었다. apt 가 `nvidia-driver-580` 을 580.159.03 으로 자동 업데이트해 둔 상태에서 reboot 으로 kernel module reload 가 안 돼 user-space lib 과 kernel module (580.126.09) 이 어긋나 있었다. 62 일 무재부팅이라 누적된 갱신이 한꺼번에 누적된 상태. dkms 가 현재 + 다음 커널 양쪽에 새 module 을 빌드 완료해 둔 게 확인돼 reboot 권장으로 결론.

### 2.2 재부팅 + 자동 재기동 점검

사용자가 직접 sudo reboot 트리거. 부팅 후 호스트 nvidia-smi 가 580.159.03 으로 깔끔하게 올라왔고 v3 컨테이너 17 개 중 vllm-llm 하나만 exit 127 로 떨어진 사례가 보였다. 호스트 드라이버가 갈리는 시점과 컨테이너 시작이 겹친 듯. v3 compose 절대경로 명시 up 으로 복구 (`docker compose -f /home/youngs75/projects/prime-jennie-runtime/docker-compose.yml --project-directory /home/youngs75/projects/prime-jennie-runtime up -d vllm-llm`) — ssh 원격 쉘은 working dir 이 home 이라 cd 가 안 먹는 점도 같이 발견. healthy 후 News pipeline LLM 호출 정상 재개.

데이터 손실은 없었다. v3 Postgres 의 `prime_jennie_v3` DB 에 sheet 1,136 건 + 5-22 발행 14 종 + 결정론 코어 conviction 29 건 그대로, Redis 118 키 보존, daemon heartbeat 6 종 (price-scheduler / fast-loop / news-pipeline / slow-loop / job-worker / coordinator-listener) 모두 발행 중.

### 2.3 메모리 정정 — v2 잔존 인프라 표기 outdated

점검 중 글로벌 메모리 `prime-jennie-family.md` 의 "v2 잔존 인프라 3 개 (vllm-llm/vllm-embed/qdrant)" 표기가 outdated 라는 점이 드러났다. qdrant 와 vllm-embed 는 2026-04-21 News pipeline 메타데이터 RDB 전환 때 사용처가 사라졌고 vllm-llm 도 v3 compose 단독 service 로 이관됐다. 실제 v2 잔존은 사실상 없음. 글로벌 메모리 v2 잔존 섹션을 현 상태로 갱신 push (commit `d6928f0`). 핸드오프 0001 이 v2 명령을 알려준 게 이 outdated 표기에서 온 거였다.

### 2.4 Phase 0 #1 conviction-outcome script 에 r3 (7 팩터 개별) 추가

기존 `scripts/analyze_conviction_outcome.py` 가 r1 (전체) / r2 (strategy_tag 별) / r5 (시간대) / r6 (Nth 추천) 까지만 보고 있었다. 5-24 0001 핸드오프 §4 가 명시한 r3 (7 팩터 개별 × pnl_pct) 가 빠져있는 것을 확인하고 추가. `screening_candidates.factors_json` 에서 결정론 코어 quant.py 의 7 팩터 (momentum / quality / value / technical / news / supply_demand / sector_momentum) 각각 Pearson r 산출. ma_score / quant_total 은 conviction 과 동치라 r1 중복 회피로 제외. ### 2.5 Phase 0 #3 Macro 게이트 역행 차단 가드 설계

PG 에서 5-15 macro_runs 사실관계를 다시 확인했다. KST 13:36 closed (KOSPI -4.83%) → 13:42 open (KOSPI -4.46%) → 14:12 다시 closed 의 6 분 + 30 분 역행 윈도. KOSPI 가 회복된 게 아니라 0.37 포인트 미세 변동했을 뿐인데 LLM 이 정반대 결론을 낸 사례. 그 8 분 윈도 자체엔 매수가 들어가진 않았지만 (executions 0 건) 같은 패턴이 재발하면 매수 들어갈 위험 잠재.

세 옵션을 비교 후 거래일 단방향 잠금 권장. 같은 거래일 안에 macro 가 한 번 closed 로 켜진 뒤에는 후속 LLM 호출이 open 이라도 결정론 layer 가 closed 로 덮어쓰고, 다음 거래일 시초부터 LLM 판단을 다시 신뢰. cooldown 윈도 (N 시간 임계) 는 single-day overfit 위험, 정량 조건 동반은 결정론 layer 가 LLM Macro 의 일을 흉내내게 되어 minyoung-mah 학습과 충돌. 한 번 closed 가 켜진 사실은 LLM 의 다음 호출이 되돌릴 권한을 갖지 않는다는 정신.

구현 자리: `prime_jennie_runtime/slow_loop/macro/post_processor.py` 의 auto_override 다음 단계 한 함수 + 한 줄. 비활성 env 는 `MACRO_REVERSAL_GUARD_DISABLED` (auto_override 패턴 따라). 구현은 별도 세션. design doc 108 줄 commit `04f336c`, `prime-jennie-runtime/.ai/designs/2026-05-24-phase0-3-macro-reversal-guard.md`.

## 5. 중요 참고사항

호스트 nvidia 드라이버 자동 업데이트 + 무재부팅 누적이 한참 쌓이면 vllm-llm 컨테이너 recreate 가 ABI mismatch 로 깨질 위험이 있다. 다음 재부팅 시점도 dkms 가 빌드 완료한 상태인지 먼저 확인. 호스트 드라이버 변경이 있는 reboot 뒤엔 컨테이너 다 올라온 듯 보여도 vllm-llm 한 줄 명시적 확인 권장.

ssh 원격 쉘은 working dir 이 home 으로 시작한다. `cd && docker compose` 패턴이 SSH 명령 안에선 안 먹는 경우가 있어 `docker compose -f <abs> --project-directory <abs>` 절대경로 형태가 안전.

5-15 사례 한 건만 보고 Phase 0 #3 가드를 정한 게 아니다. minyoung-mah 학습 (prompt 로 LLM 결정론 제어 금지, enforcement 는 별도 layer) 과 master doc §3 의 원칙을 macro 도메인에 적용한 결과. cooldown 임계 N 의 사전 결정 금지, 정량 조건으로 LLM 일 흉내내기 금지 두 가지가 옵션 배제 근거.

Phase 0 #1 r3 가 의미를 가지려면 outcomes 표본 30 건 이상. 결정론 코어 5-22 발행분 부터 자연 누적이고, 5-23·5-24 휴장이라 0 건 출발. 한 주 풀 거래로 평균 7 ~ 8 건 누적되는 페이스라 4 ~ 5 주 후 첫 의미 표본. 그 사이엔 결과 카드 보고 너무 일찍 해석하지 않는다.

v2 잔존 인프라 표기 정정 사례에서 한 가지 일반 학습. 사용자가 다른 머신에서 보는 글로벌 메모리에 outdated 명령 (qdrant/vllm 재기동 v2 compose 경로) 이 박혀 있으면 그게 다음 세션의 LLM 행동을 잘못 이끈다. 핸드오프 0001 의 v2 compose 추정 명령이 이 outdated 표기에서 온 거였다. 다음에도 인프라 구조가 바뀌면 글로벌 메모리의 인프라 섹션을 같이 갱신한다.
