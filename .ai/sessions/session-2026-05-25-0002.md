### 2.2 Logs 페이지 false-positive ERROR 두 단계 fix

control-ui Logs 페이지가 자기가 보낸 `/api/logs/stream?service=...&level[]=ERROR` 요청을 nginx access log 로 받은 다음, line 안의 "ERROR" 단어를 잡아서 자기 요청을 ERROR 로 라벨링하던 자가 충돌. HTTP status 는 다 200 이었다.

1차 fix (`d1d5d2d`) 로 nginx access log 패턴 (`" 200 11 "` 같은 status+bytes) 을 우선 매칭해 HTTP status code 로 분류했는데, 사용자가 dashboard 서비스 로그 (`INFO: ... 200 OK` uvicorn 형식) 로 가서 또 false-positive 신고. uvicorn 은 status 다음에 "OK" 텍스트가 와서 `" \d{3} \d+ "` 패턴 매칭 실패 → fallback 의 `\bERROR\b` 가 다시 잡힘.

2차 fix (`17ee451`): 라인 머리의 `INFO:` / `ERROR:` / `WARNING:` prefix 를 가장 먼저 매칭 (Python logging / uvicorn 표준 형식). 우선순위는 prefix → HTTP status (`" \d{3}(?:\s|$)`, "OK" 도 매칭 가능) → fallback `\bERROR\b`. 세 형식 (nginx / uvicorn / Python logging) 모두 정확 분류.

이 과정에서 docker build cache 가 src 변경을 무시하는 사고가 같이 나왔다. 첫 빌드 후 dist 의 Logs chunk hash 가 빌드 전후 정확히 같았고 (`Logs-D1MEPKb8.js` 두 번), dist 안에 새 코드 흔적이 없었다. `docker build --no-cache` 강제 재빌드하니 정상 hash (`Logs-CqXbXmUr.js`). 원인은 BuildKit layer cache 가 host filesystem 변경을 놓친 정황이지만 정확한 트리거는 미상. 이후 control-ui 수동 빌드는 매번 `--no-cache` 로 진행.

### 2.3 Scout 좌측 RUNS 카드가 아래 Candidates 카드와 겹침

Scout 페이지에서 좌우 분리 scroll grid 가 `maxHeight: "calc(100vh - 160px)"` 만 받고 `height` 가 없어, 좌측 column 의 RUNS list 가 길어지면 grid 영역을 넘어 stretch. 그 아래에 grid 의 형제로 위치한 Candidates Card 와 정확히 같은 좌표에서 글자가 겹쳐 찍혔다. 사용자가 캡쳐로 신고.

Macro 페이지도 같은 패턴이지만 grid 아래 형제 카드가 없어서 겹침이 안 드러났던 자리.

## 5. 중요 참고사항

이번 세션에서 학습 메모리 3 건이 추가됐다. 다음에 같은 함정 안 빠지도록 의식할 자리.

`feedback_log_level_parser_multi_format` — 로그 level 파서는 단일 access log 포맷만 가정 금지. 우선순위 prefix (`INFO:` / `ERROR:`) → HTTP status (`" \d{3} `) → `\bERROR\b` fallback. nginx / uvicorn / Python logging 셋 다 다른 형식.

기존 메모리 중 한 자리도 갱신 권장 — [LLM tier 할당](project_llm_tier_assignment.md) 의 "Scout/Macro/Briefing/WSJ 전부 DeepSeek, Opus 실사용처 0" 인데, 이번 세션 통계 누락 보강으로 호출처 실측 표는 5 service (macro / news_global_digest / briefing / telegram_intent + news_analysis vLLM) 로 늘었음. macro_shadow 는 비활성 유지. 다음 세션 시작 때 한 번 fact-check 권장.
