## 중요 참고사항

### Stream XLEN vs lag 구분
- **XLEN** = stream 전체 엔트리 수 (`XADD` 하면 +1, MAXLEN trim 에서만 감소,
  XACK 로는 감소 안 함)
- **lag** (per consumer group) = `last XADD id - last-delivered-id` — group 이
  아직 read 안 한 엔트리 수. 진짜 backlog 지표.
- 운영 모니터링 / 부하 판단은 **lag 기준**. XLEN 은 MAXLEN 과 approximate 로
  오해 유발.

### Legacy consumer group 주의
2-stage → 1-stage 같은 stream 파이프라인 구조 리팩터링 후, Redis 의 구 consumer
group 이 잔존해 lag 로 stream 을 "잠그는" 현상. 반드시 `XGROUP DESTROY` 수동
정리. 향후 migration 훅으로 자동화 고려.

### Qwen3 드레인 특성
- Structured JSON 출력 + 한국어 고유명사 보존 요구로 토큰 당 비용 높음
- 실측 **2.3 req/sec** (138/min) — vLLM `max-num-seqs=64` · `gpu-memory-utilization=0.88`
  기준
- 처음에 "14/min" 으로 과소 측정된 건 stream 비어 idle polling 포함된 샘플
- 진짜 steady-state 측정은 **"analyzed_at > NOW() - INTERVAL '2 min'"** 카운트가
  정답

### NVIDIA 드라이버 580 + RTX 3090 소음
- `temperature.memory` N/A — 580 driver 가 GDDR6X junction temp 쿼리 차단
- Linux headless 팬 제어는 우회 (dummy X) 필요. Windows Afterburner 수준의 UX
  없음
- 즉각 완화: `nvidia-smi -pl <lower>` 로 power cap 내림 (재부팅시 서비스로
  유지해야)

### Scout/Macro 메타데이터 필드 사용 규칙
- `NewsScoreEntry.event_types` 은 **없을 수 있음** (기사 0건). 코드에서 `.get()`
  또는 `in` 으로 안전 접근. Scout prompt 에도 이 패턴 명시됨.
- 코드 schema 가 변경된 후 Scout 가 즉시 활용하지 않을 수도 있음 — LLM 이
  새 필드를 발견하기까지 몇 회 warmup 필요. hit rate 측정 필요.

### News UI / News Events 통계
- 오늘 재분류로 전체 누적 통계가 shift 함 — control-ui News 페이지의
  `/api/news/stats` 는 analyzed_at 기준이므로 "재분류 이후" 결과가 포함됨.
  시계열 그래프는 sentiment/event_type 변동 관찰 가능.
