영석님이 딴지 글(889323830, "외국인 선물 포지션으로 월요일 시장을 판단해 보시라")을 가져와

배포·검증했다. 마지막에 민지 리뷰를 받아 롤오버 결함을 고쳤다. 일요일이라 장은 닫혔고,

## 한 일

### 1. 원천 실측 — 글의 1차 신호는 수집 불가, 근거 관측치는 수집 가능

MS-01 kis-gateway 컨테이너에서 실계정으로 KIS 를 직접 두드려 확인했다. 결론이 뒤집혔다.

**투자자별(외인/기관/개인) 선물 순매수는 못 받는다.** KIS 국내선물옵션 API 43개에 투자자별
엔드포인트가 아예 없고, 국내주식 투자자매매동향(FHPTJ04030000)에 선물 시장구분(F/101/0001)을
넣으면 **rt_cd=0 으로 정상 응답하면서 값이 전부 0** 으로 온다. 에러가 아니라 조용한 0 이라
수집 코드가 "성공"으로 기록하고 넘어갈 최악의 실패 모드다 — 실측 안 했으면 몇 달치 0 을
쌓고 나서 알았을 것이다. KRX 는 회원제 차단 + OpenAPI 카탈로그에 투자자별 없음(기존 메모리).
딴지 글의 이미지 2·3·4 가 전부 여기 해당한다.

**그런데 그게 바로 글이 "믿지 말라"고 한 데이터다.** 저자의 주장은 "외인 선물 순매수를
보라"가 아니라 "장중 합성 포지션·전매도 환매수 혼합·야간 청산 누락 때문에 그 숫자를 믿지
말라"였다. 못 받는 쪽이 어차피 못 믿을 쪽이었다.

**저자가 실제 근거로 쓴 관측치는 전부 받아진다.** KIS 선물 시세(FHMIF10000000, `F`)로 정규
KOSPI200 선물 9월물 `A01609` 를 조회하니 미결제약정 **157,869** — 글에 실린 HTS 화면 숫자와
정확히 일치하고, 당일 최고가 1248.90 도 글의 "13:09 최고점 1248.90"과 맞는다. 베이시스·
이론가·괴리율까지 한 번의 호출로 나온다. OI 와 베이시스는 합성 포지션으로 감출 수 없는
집계치라 신뢰도 면에선 투자자별 순매수보다 낫다.

**종목코드 체계도 실측으로 확정했다**: `A` + 상품(`01`=정규, `05`=미니) + 연도 끝자리 + 월 2자리.
`A01609`=정규 2026-09월물, `A05608`=미니. 결제월은 분기물(3/6/9/12)뿐.

**백필은 불가능하다.** 일별 차트(FHKIF03020100)의 일별 배열엔 OHLCV 뿐이고 미결제약정이 없다.
OI 는 "오늘 스냅샷"으로만 온다 → 즉시 백테스트 불가, 전방 적재만. 영석님이 전방 적재로 가기로
결정했다.

### 2. 수집기 구축 (commit b459105, migration 028)

게이트웨이에 `GET /api/futures/kospi200` 을 추가하고(파생 API 통로가 처음 열렸다),
`jobs/market_inputs.collect_futures_oi(slot)` → `futures_oi_snapshots` 로 적재한다.
하루 4슬롯: preopen 08:50 / close 15:50 / night_open 18:10 / night_close 익일 05:05(화~토).

핵심은 마지막 슬롯이다. night_close 는 trade_date 를 하루 당겨 적재하므로 **같은 날짜의
close ↔ night_close 미결제약정 차이가 곧 '낮에 쌓인 포지션 중 밤에 접힌 양'** 이 된다.
글의 핵심 주장을 그대로 재는 필드다. night_close 의 휴장 가드는 gateway 가 아니라 DB 로
한다(그 trade_date 에 close 행이 있나) — 금요일 밤 세션이 토요일 새벽에 끝나는 구조라
'오늘' 기준 거래일 판정이 어긋나기 때문. 실제로 토요일 기준으로 돌려 스킵되는 것까지 봤다.

**게이트에는 연결하지 않았다.** VKOSPI·연기금 때(6-24)와 같은 규율 — 예측력이 데이터로
확인되기 전엔 매크로 입력으로 승격하지 않는다. 지금 매매 판단에 미치는 영향은 0 이고,
얻은 건 예측 능력이 아니라 관측 능력이다.

### 3. 민지 리뷰 — 승인 + 보완 3건, 롤오버는 코드로 수정 (commit 2c82d37, migration 029)

민지가 "조용한 0 을 잡아낸 게 제일 가치 있는 발견", "판정 기준을 결과 보기 전에 못박은 것과
gate 미연결 규율이 관성이 된 것 자체가 자산"이라며 승인했고, 보완 3건을 냈다.

**① 롤오버 오염 — 실질 결함이라 즉시 고쳤다.** 만기 주간엔 OI 가 근월물에서 차월물로
*이전*되는데, 근월물 하나만 찍으면 이 이전이 '청산'으로 오독된다. 판정 표본 60거래일 안에
만기가 최소 한 번 끼므로 그대로 뒀으면 분석 결과가 통째로 오염됐을 것이다. → **근월·차월
두 계약을 모두 적재**하도록 바꿨다(`is_front`, `last_trade_date` 컬럼). PK 가 이미
contract_code 를 포함해 구조 변경은 필요 없었다. 프로덕션 검증: 근월 A01609(157,869, 만기
9-10) + 차월 A01612(7,986, 만기 12-10) = 합산 165,855.

**② 캘린더 — 동작 확인 후 명시.** 네 슬롯 모두 거래일 캘린더를 탄다(평일 크론 + KIS
chk-holiday 가드, night_close 는 화~토 크론 + DB 가드). **휴장일엔 행을 아예 안 남긴다** —
forward-fill 없음, NULL 행 없음, 결측은 행 부재로만 나타난다(paper outcomes NULL 유형 차단).
다만 파고들다 함정을 하나 더 찾았다: **휴장일 *전날* 밤엔 야간장이 안 열릴 수 있어**
night_close OI 가 close 와 같아지고, 그러면 '야간 청산 0' 으로 오독된다. 세션 부재와 청산
부재를 구분하려면 **누적 거래량(volume) 델타를 같이 봐야 한다** — 야간 거래가 반영됐다면
거래량이 늘어야 한다. 분석 규칙으로 문서에 박았다.

**③ KRX 백필 커버리지 — 기대치 정정.** 백필되는 건 일별 마감 OI 뿐이라 판정 ②(베이시스)·
③(4분면)만 즉시 백테스트 가능하고, ①(야간 청산분)은 마감↔야간 구분이 필요해 KRX 과거
데이터에 야간 OI 가 따로 없으면 어차피 60거래일을 기다려야 한다. "백필하면 3개월 안
기다려도 된다"는 ②③에만 성립하는 문장이었다.

## 중요 참고사항

- **KIS 투자자매매동향 API 는 현물 전용이고, 선물 코드를 넣으면 rt_cd=0 에 값이 전부 0 이다.**
  에러가 아니라 조용한 0 — 같은 조사 반복 금지. 투자자별 선물 수급은 KIS·KRX 어디서도 못 받는다.
- **선물 과거 미결제약정은 KIS 가 안 준다**(일별 차트에 OI 없음). 전방 적재만 가능하다는 걸
  전제로 설계할 것.
- **선물 단축코드**: `A` + `01`(정규)/`05`(미니) + 연도 끝자리 + 월 2자리. 분기물만 존재.
  롤오버는 "가까운 분기물 2개 중 OI 큰 쪽"으로 자동 추종하되, **적재는 두 계약 다 한다**.
- **분석 시 함정 둘**: (a) OI 델타는 근월+차월 합산으로 — 안 그러면 롤오버가 청산으로 보인다.
  (b) 야간 OI 가 마감과 같으면 '청산 0' 이 아니라 '세션 없음/미반영'일 수 있다 — volume 델타로
  구분한다.
