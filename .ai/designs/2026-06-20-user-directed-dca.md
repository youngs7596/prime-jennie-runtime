## 1. 결정 (확정)

- **격리**: slow/fast loop·tracker·시트와 무관한 독립 경로. 자체 `dca_campaigns`/
  `dca_slice_executions`(migration 026). paper 알파 측정에서 구조적으로 제외(측정이 보는
  테이블에 안 들어감).
- **주문 = 일반 시장가**(ORD_DVSN "01"). 사용자 확정. 게이트웨이는 IOC 미지원이고, 기존
  부분체결 처리(체결분 확인 → 잔량 취소 → 재조회로 terminal 확정)가 IOC 의도를 코드로
  달성한다. 초대형주 14:30 시장가는 즉시 전량체결돼 IOC 와 사실상 동일. 공유 게이트웨이
  주문 스키마 수정 없음.
- **집행 = 게이트웨이 직접 호출**(`fast_loop/kis_client.py` 재사용). control stream→consumer
  경로는 안 쓴다 — 그 경로의 tracker dedup 이 같은 종목 재매수(10슬라이스)와 충돌한다.
- **무장 = 텔레그램 echo + "확인"** 2단계(/accept 패턴). 프리셋(production/smoke/dryrun)으로
  오타 방지. smoke 만 운영자가 종목을 붙인다.
- **구동 = job-worker tick** cron `* 9-15 * * 1-5`. 14:30 예정·급락 가속·VI 재시도를 한
  경로로 합쳐 상호배제를 단순화.

## 2. 상태기계 (tick 가드 우선순위)

매 tick, 활성 캠페인마다: reconcile(in-flight 정리) → G0 cap 도달 → G1 VI 재시도 due →
G2 오늘 처리됨 → G3 급락 가속 → G4 14:30 예정. 첫 매치에서 분기·return. 한 tick 한 종목
한 집행. 핸들러는 예외를 밖으로 던지지 않는다(scheduler 재호출 = 이중집행 위험).

급락 가속(시가대비 ≤-4% 또는 전일종가대비 ≤-5%)은 다음 예정 슬라이스를 당겨 집행할 뿐
추가 매수가 아니다 — 누적 cap 불변. 같은 날 이중집행은 `today_settled` + `slices_done`
두 겹으로 막는다(설계 검토 때 별도 expired 도장은 일시 실패 시 그날 슬라이스를 날려 제거).

roll-over 예산은 "목표 누적 − 실제 누적"이라 부분체결·패스를 다음 슬라이스가 자동 흡수.
모든 예산이 `cap − cumulative`로 클램프돼 `cumulative ≤ cap` 불변식이 성립.

VI 페일세이프: 주문 거부 시 retry_at(+5분)을 PG 에 영속하고 다음 tick 이 1회 재시도(블로킹
없음). 재실패면 패스 + 예산 이월. 마감 임박(15:10 이후)이면 재시도 없이 바로 패스.

crash 복구: 주문은 나갔는데 PG 기록 전 죽으면, submitted 행을 order_no 로 재confirm 하거나
KIS 원장(`/api/executions`)과 대조해 멱등 복구. 이중 매수를 만들지 않는다.

## 3. 안전요건 (명세 6개 전부 충족)

누적 cap 코드강제 / 멱등성(slice_key UNIQUE + 원장 대조) / confirm echo / persist(전 상태
PG, 재기동 이어가기) / VI 페일세이프 / 건별·일별 cost cap.

## 4. 검증 사다리 (본자금 전, 순서 고정)

`/dca arm dryrun 확인`(실주문 없이 며칠 로직 확인) → `/dca arm smoke <저가종목> 확인`(소액
실거래 1사이클) → `/dca arm production 확인`(본자금). 장중 배포 금지 가드 준수.

## 5. 집행 시각 14:30 → 14:00 (백테스트, 2026-06-20)

명세는 14:30 고정을 단순성 우선으로 못박았지만, 종목·금액이 고정이라 자유변수가 "언제"
하나뿐이고 과거 분봉으로 답이 나오는 측정 문제라 실제로 백테스트했다(상세
`.ai/analyses/2026-06-20-dca-entry-time.md`). MS-01 KIS 1분봉 39거래일 전체 세션 기준:
늦은 오후(15:00~15:20)는 14:30 보다 안 좋았고(삼성 더 비쌈, 하이닉스 비슷), 14:30 은 진짜
종가를 이기거나 비겼다 — 더 늦게 가는 건 손해. 싼 쪽은 앞이었고, 14:00 이 두 종목 모두
14:30 보다 일관되게 조금 싸면서(개장을 뺀 시각 중 t값 최강) "오후·방향 확인 후·개장 노이즈
회피" 명분을 지켰다. 그래서 기본 집행 시각을 14:00 으로 정했다(효과는 작고 통계는 약함 —
lean 수준). 개장(가장 쌈)은 갭·변동성이 커 피했고, 거래량·신호 기반 복잡한 타이밍은 즙이
안 나와 도입 안 함. 집행 시각은 캠페인별 execute_at_kst 라 tick 이 종목별로 읽는다(향후
종목별 차등 여지). 판단·감시를 LLM 에 두지 않는다는 원칙은 유지.
