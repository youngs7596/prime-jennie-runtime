## 중요 참고사항

### 본 세션의 architectural 학습

1. **병렬 agent + 사전 contract 고정** — 4 agent worktree 격리 + 명세된 stream
   key/publish API/listener API 로 충돌 0. 1850 줄 + 361 줄 신규를 단일 검증
   세션에 통합. 다만 agent 가 자기 영역 외 공용 인프라 (Notifier.client 등)
   를 만지는 대신 우회 패턴 (private access) 으로 처리한 부분이 후속 issue
   로 남음 → 사전 contract 에 "공용 인프라가 부족하면 만들지 우회하지 마라" 가
   추가될 수 있음.

2. **5 후속 issue 의 본질** — 모두 "agent 가 자기 영역만 챙기느라 inter-layer
   계약을 우회"한 데서 발생. 즉 Coordinator 의 "외톨이 패턴" 의 작은 reflection.
   agent 작업도 외톨이 패턴이 발생할 수 있음을 본 세션에서 확인.

3. **idempotency-as-design** — listener 의 stream_msg_id UNIQUE 도입은 ACK 실패의
   transient 문제 + retry 인과를 한 layer 에서 단정. 이게 lifecycle 안전성
   (design §0 원칙 #4) 의 구체 사례.
