### 2) Root cause — 다층 미구현

코드 grep / docs 정독 / v2 reference / git log 결과 **3 레이어 명세 누락**:

1. **scout prompt** (`scout/prompts.py:140`) — entry_hint 예시가 `trigger` 만,
   conditions 누락 → DeepSeek 가 빈 리스트 반환
2. **slow-loop strategy engine** — conditions_hint pass-through 만, 정책 기반
   후처리 없음
3. **fast-loop consumer + tick_loop** — conditions evaluator / pending queue
   자체 없음. consumer 가 시트 받자마자 entry_executor 호출 → 시장가 발사

추가로 **entry/exit_executor 의 PG `executions` insert / `positions` upsert
코드 자체 없음** (설계 단계 누락). docstring 에 PG persist 단계가 아예 없는 채로
Phase 1 Track C 단일 commit `7906785` 으로 들어왔고 이후 수정 0건.

POSITION_SHEET_SPEC.md §4.1 / §4.3 명세 (사용자 가설과 일치):
> `limit` trigger: 호가창 확인 후 `conditions` 전부 만족 시에만 발행
> conditions 전부 AND. 어느 하나라도 실패 시 진입 보류. **valid_until 내 재평가**
> generated_at 이 09:00 KST 이전이면 → Executor 는 시트를 받아도 장 개장까지 대기

v2 (`services/buyer/executor.py:109`) 도 `process_signal(signal: BuySignal)` 패턴.
scanner 가 실시간 신호 detect → buyer 가 신호 시점 매수. v3 는 이 BuySignal 을
"시트 + conditions" 로 추상화한 것 — 그런데 fast-loop 측 evaluation 이 빠진 채.

## 중요 참고사항

### 5-06 의 패착 본질 — 외형 신호 vs 도메인 정확성

5-04 핸드오프 시점에 "STOP 해제 + 매매 운영 진입" 으로 적힌 게 사용자 인식엔
"준비 끝, 가동" 으로 읽혔지만 실은 **매매 가능 상태로 만든 것뿐**. 매매가
명세대로 동작할 거란 보장과는 별개의 사실. 887 tests 통과 / 컨테이너 17/17
Up / heartbeat / cron success / API 200 — 전부 외형 표층. fast-loop 의 entry
path 가 실 시장에서 한 번도 안 돈 채로 가동.

명세에는 conditions 4종이 정의되어 있고 시트 schema 도 살아있었지만:
- write 측 (slow-loop) 이 conditions_hint 를 채우지 않음
- read 측 (fast-loop) 이 conditions 를 evaluate 하지 않음
- 양 끝이 죽은 채 schema 만 외관상 존재

회귀 테스트도 "현 코드 동작 검증"이라 명세 vs 구현 갭 안 잡힘. test_consumer /
test_entry_executor / test_integration 모두 즉시 매수 stub 으로 짜여있어
명세 누락이 silently 통과.
