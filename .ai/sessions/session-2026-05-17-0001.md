## 중요 참고사항

### architectural 학습

1. **단일-day 정량 검증의 over-fitting** — G2 v1 의 "5-15 8/10 차단" 충분 근거 가정이 평상 day Pre-flight 에서 익절>손절 차단 결과로 명백히 무너짐. **Pre-flight 사전 검증의 가치 — design §7.4 룰이 정확히 작동**. n<30 single-day 정량을 design 의 충분 근거로 보지 말 것 (`feedback_single_day_overfit`).

2. **가격 기반 지표는 outcome 예측력 없음** — overextension (close_to_high_60d / r20d / r5d) 같은 가격 단위 지표가 손익 구분 못함. 진짜 outcome 예측 변수는 **상태 변화 신호** (시초 갭다운, KOSPI gate 깨짐, thesis 조건 무효) — G3 / G6 의 방향이 본질적으로 맞음.

3. **entry vs hold 가드의 직교성** — 같은 지표 (r20d) 라도 entry 가드 (G2) 와 hold 가드 (G6) 는 다른 layer 에서 다른 의미. G2 부정 결과가 G6 catalog 의 r20d_above_threshold 추가를 막지 않음. design 의 직교성 (G1~G5 entry vs G6 hold) 의 실제 운영 효과.

4. **점진 도입 패턴 (Phase A/B/C)** 의 가치 — Phase A 는 schema + 영속만 (실행 영향 0) → 1주 측정 → Phase B advisory (log only) → Phase C enforce. 운영 안전 + 데이터 누적 균형. G6 design 의 이 패턴이 5-14 Coordinator design 의 advisory → enforce 원칙과 동일.

5. **외부 LLM 문서 활용 — 지향점만 추출** — 5-16 Web Claude (민지) 문서가 우리 시스템 못 본 상태로 작성됐고 처방 대부분 우리 이미 보유. **거의 모든 처방 제외 + 1순위 신규 가치 (thesis 객체화) 만 G6 으로 추출** 한 패턴이 외부 input 처리의 정공법.
