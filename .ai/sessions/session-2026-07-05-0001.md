정전 복구 세션이다. 오늘 낮 12시쯤 집 정전으로 MS-01 과 eGPU 가 다 꺼졌다가

분석 과제(7-3 세션이 남긴 이월분)에는 손을 못 댔다 — 복구가 우선이었다.

## 한 일

### 1. 정전 후 MS-01 종합 점검
재부팅 직후엔 SSH 도 안 됐다(ARP 조차 안 잡힘). 라우터는 멀쩡했으니 MS-01 만 안
올라온 상태였고, 사용자가 수동으로 다시 켜 12:52 에 부팅됐다. 컨테이너 21개 중 20개는
자동 복구, DB·Redis·게이트웨이(잔고조회 200)·느린 루프·빠른 루프·스케줄러 둘 다
정상 기동을 확인했다. 디스크 9%, 메모리도 여유.

### 2. eGPU 가 자동으로 안 붙었다 — 유일한 고장
재부팅 후 그래픽카드(RTX 3090)가 PCI 버스에 아예 안 보였다. 썬더볼트 eGPU 인클로저의
링크가 안 붙은 상태였고, 사용자가 케이블을 뽑았다 다시 꽂으니 그때서야 인식됐다
(원격으로는 못 고친다, 사람 손이 필요). GPU 가 붙자 드라이버는 자동으로 올라왔다.

### 3. 죽어 있던 로컬 LLM 을 살려 뉴스 파이프라인 복구
GPU 가 없던 동안 로컬 GPU LLM 서버(vllm)가 "driver not loaded" 로 죽어 있었고, 이게
뉴스 파이프라인의 이벤트 추출을 연결 에러로 조용히 실패시키고 있었다. **이번에 처음
확인한 사실: 로컬 GPU LLM(Qwen3-30B)이 뉴스 이벤트 추출에 실제로 쓰인다.** 예전
기억의 "LLM 은 전부 외부 API(DeepSeek)" 는 옛말이 됐다. GPU 복구 후 vllm 을 재시작하니
모델이 정상 적재됐고(GPU 22GB 점유), 뉴스 파이프라인이 다시 붙는 것까지 확인했다.

### 4. 전력 제한이 부팅 때 안 걸려 팬이 풀로 돌던 것 → 200W 재적용 + udev 근본 개선
재부팅 후 GPU 전력 제한이 기본값(370W)으로 풀려 있어 LLM 추론에 팬이 100% 로 돌아
무척 시끄러웠다. 원인은 전력 제한 서비스(`nvidia-power-limit.service`, 200W)가 부팅
직후 GPU 를 60초만 기다리다 못 찾고 실패했기 때문이다 — eGPU 가 그 창 안에 안 붙었고,
케이블을 나중에 꽂았을 땐 이미 서비스가 죽어 있었다. 서비스를 수동 재실행해 200W 를
다시 걸어 소음을 잡았다(온도 67→54도).

근본 개선으로 udev 규칙을 추가했다. GPU 가 PCI 에 등장하는 순간(케이블을 언제 꽂든)
전력 제한 서비스를 자동 재실행하는 규칙이다. dry-run 검증에서 실제 GPU 에 규칙이
매칭돼 서비스 재실행을 결정하는 것까지 확인했다. 실제 강제 이벤트 재발생(end-to-end)은
root 권한이 없어 눈으로는 못 봤지만, 진짜 정전·케이블 재연결 상황에서는 커널이 이벤트를
내고 udev 데몬이 root 로 처리하므로 이 권한 문제와 무관하게 작동한다.

### 5. repo 정리 (이번 커밋)
- `infra/udev/99-nvidia-power-limit.rules` 신규 — 배포본 그대로 버전 관리.
- `infra/systemd/nvidia-power-limit.service` 의 전력값이 repo 는 250W 인데 배포본은
  200W 로 어긋나 있었다. 배포 실체(200W)에 맞추고, udev 보완 규칙과 설치 절차를 주석에
  반영했다. 278 → 250 → 200 인하 이력도 정리.
