### 3. DCA 백테스트 A vs C — 지시서 실행 (핵심)
민지님 지시서대로 데이터 인벤토리(0번)부터. 발견이 결정적이었다.

- 운영 DB 의 종목 일봉은 KIS 게이트웨이 경로라 3.5개월치뿐, 분봉은 2개월(KIS 한계로 과거
  확장 영영 불가), VKOSPI 는 아예 안 받는다. 그래서 의뢰서의 전략 B(분봉 RSI+VKOSPI+수급
  확인게이트)는 입력 데이터가 없어 **구조적으로 측정 불가** → 폐기. 민감도 분석(D)도 과거
  강제매도 동종 표본이 없어 불가.
- A·C 는 가격만 있으면 되니, Yahoo 로 2020-01~현재 일봉을 백필했다(삼성·하이닉스·KOSPI
  수정종가, 시스템 KOSPI −9.99% 와 일치하고 네이버 fchart 와 폭락일 종가 Δ0.00% 교차검증,
  구간 내 분할 없어 원종가가 연속).
- KOSPI 첫 −4% 룰로 이벤트 자동 추출. 실제역사 4건(2020-03·2020-06·2024-08·2025-04)을
  주력 코호트로, 시뮬2026 3건은 참고용(호라이즌 미완)으로 분리.

**결과:** 실제역사 4건에서 C(풀백 가속)는 A(균등)를 못 이겼다. 6개월 평균 −0.86%p, MDD 는
0.6%p 더 깊다. 배수에 0.75·1.5를 곱하든 트리거를 단일일로 바꾸든 결론이 음(−)으로 robust.
열세는 거의 2020 코로나 한 건이 끌었는데, 들여다보니 C 의 구조적 약점이 그대로였다 —
누적 낙폭이 커질수록 배수를 키워 2020-03-16 에 실탄을 다 소진했는데, 삼성 바닥은 닷새 뒤
03-23 이었다. 가장 큰 슬라이스를 바닥 전에 털어 평단·MDD 양쪽에서 손해. 결정 변수는 폭락
깊이가 아니라 바닥까지 걸린 시간이고, 빠른 폭포·늦은 바닥이면 C 가 진다.

### 4. 전략 A 영구 채택 — 가속 비활성 (commit af1f58e)
엔진의 급락 가속 경로를 `ACCELERATION_ENABLED=False`(tick.py 모듈 상수, G3 게이트)로 잠갔다.
가속 코드 자체(accel_should_fire/accel_slot)는 삭제하지 않고 잠가뒀다 — 보고서가 적은 재설계
여지(단일일 트리거+완만한 배수+예산 유보)를 남기려고, 상수만 True 로 되살아난다. 가속 단위
테스트는 상수를 켜서 잠든 경로를 계속 검증하고, "급락일에도 가속 안 하고 예정 시각에만 base
집행"이라는 기본-A 테스트를 새로 넣었다. DCA 47건 통과, 린트 통과.

### 5. 라이브 엔진 ≠ 백테스트 C 를 확인
중요한 사실을 코드로 바로잡았다. 라이브 엔진의 "가속"은 백테스트 C 처럼 슬라이스를 1.5~3배로
키우는 게 아니라, 예산 산식이 "슬라이스 N까지 누적 = base × N"으로 고정돼 각 슬라이스가 base
크기 그대로다. 가속은 다음 base 슬라이스의 시점만 앞당기고, 하루 한도+이중집행 가드로 하루 한
슬라이스가 최대다. 그래서 라이브는 애초에 백테스트 C 의 실패 모드(바닥 전 소진)에 노출된 적이
없었다. A 채택은 사실상 라이브를 그대로 두고 timing 당겨오기만 끄는 것이다.
