# 세션 정리 — 2026-06-17-0001

6-16 핸드오프가 남긴 실시간 적재 확인에서 시작해, 디스크 이야기로 번지면서 보존 정책을
바꾸고 Docker 를 크게 정리한 세션. 새 기능은 없고, 가동 중인 것을 검증하고 운영 결정을
몇 개 내렸다. 네 갈래다 — 실측, Docker 정리, 보존 영구화, 그에 딸린 코드 정리.

## 1. 실시간 적재 실측 — 정상 (6-16 두 미결 종결)

개장 직후 운영 DB 를 직접 조회해 6-16 에 붙인 실시간 체결·호가 적재를 검증했다.

필드 인덱스는 맞았다. 호가 10단계가 10만 행 넘게 전부 매도 오름·매수 내림으로 단조
정렬돼 있었고(인덱스가 뒤섞였다면 깨졌을 부분), 길이 오류·음수 잔량·교차 호가가 0이었다.
체결구분도 매수·매도로 제대로 갈렸고 체결강도·가격·체결량 모두 상식 범위였다. 스트리머
인덱스는 손댈 필요 없다.

틱 양도 쟀다. 20 종목 기준 하루 약 0.45GB 가 쌓이고 대부분이 호가다(호가는 체결될 때가
아니라 호가창이 바뀔 때마다 들어와 양이 훨씬 많다). 이 수치가 아래 디스크 판단의 근거가
됐다.

## 2. Docker 정리 — 128GB 회수

디스크 질문을 파다 보니 MS-01 의 사용 공간 265GB 가 거의 전부 Docker 였다(이미지 153GB +
빌드 캐시 106GB). 우리가 쌓는 DB 데이터는 다 합쳐 2.4GB 로 디스크와 무관했다. 사용자
지시로, 구동 중인 컨테이너가 쓰는 이미지만 빼고 전부 정리했다 — 형상관리가 있으니 롤백용
이미지를 남길 이유가 없다는 판단이었다. 빌드 캐시 101GB + 안 쓰는 이미지(미적용 vLLM
신버전 등)를 비워 사용량이 265GB(16%)에서 137GB(8%)로 줄었다. 컨테이너 21개 전부 그대로
돌고, 깨진 것 없다.

## 3. 보존 정책 — 90일 자동삭제 폐기, 영구 보관

원래 보존 정리 잡이 실시간 체결·호가를 90일 기준으로 지우게 돼 있었다. 사용자가 바로잡았다 —
KIS 가 과거를 안 주는 휘발성 데이터를 90일만 두는 건 이 시스템의 취지에 정면으로 어긋난다.
prime-jennie 를 접을 때까지 영구 보관하는 게 맞다.

처음엔 DB 잡 설정에 `realtime_days=36500` 을 넣어 우회하려 했는데, 확인해 보니 그 잡의
핸들러가 `days` 만 받고 `realtime_days` 는 모르는 인자였다. 스케줄러가 설정을 핸들러에
그대로 펼쳐 넘기는 구조라, 그대로 뒀으면 다음 정기 실행이 인자 오류로 깨질 뻔했다. 그래서
DB 설정은 원래대로 `{"days": 365}` 로 되돌리고, 보존은 "코드에서 실시간 삭제를 아예 제거"로
보장하는 방향으로 바꿨다.

## 4. 코드 정리 — 실시간 삭제 경로 제거 (배포는 장 마감 후)

`cleanup_old_data` 에서 실시간 체결·호가를 지우던 두 DELETE 와 `realtime_days` 인자,
`DEFAULT_REALTIME_CLEANUP_DAYS=90` 상수를 들어냈다. 이제 이 잡은 일봉(`daily_prices`,
365일, KIS 에서 재취득 가능)만 정리한다. 실시간 테이블을 건드리지 않는다는 회귀 가드
테스트를 하나 추가했다. ruff 통과, 관련 테스트 5개 통과. 코드 수정은 작업 트리에만 있고,
커밋·push(=배포)는 장중 deploy 금지라 15:30 이후로 예약해 뒀다.

## 5. 현재 상태

실시간 체결·호가 적재가 정상 가동 중이고, 90일 삭제 위협은 사라졌다(DB 설정 원복 +
코드에서 삭제 제거 예정). 분봉도 6-17 정상(204종목, 장중 적응형으로 누적). 운영은 여전히
PAUSE, 추천은 나갔으나 사용자 미매수.

영구 보관 기준 디스크 전망: 20종목에 연 약 120GB, Docker 정리 후 여유 1.6TB 라 약 12년
runway. 증설은 날짜가 아니라 여유공간 임계로 판단하면 된다. 종목 수가 늘면 비례해 빨라진다.

## 7. 중요 참고사항

- **운영 DB 접속**: `ssh prime-jennie`(192.168.31.195) → `docker exec
  prime-jennie-runtime-postgres-1 psql -U pj_runtime -d prime_jennie_v3`. DB 이름이
  `prime_jennie_v3`(계정명 `pj_runtime` 와 다름), 저장 시각은 UTC.
- **스케줄러는 잡 설정(kwargs)을 핸들러에 그대로 펼쳐 넘긴다(필터 없음)**. 핸들러가 모르는
  키를 kwargs 에 넣으면 인자 오류로 잡이 깨진다. 잡 설정 바꿀 때 핸들러 시그니처를 먼저 볼 것.
- 실시간 적재 대상은 보유+추천시트 종목(최대 20). top200 분봉은 별개(장중 적응형 REST). 혼동 주의.
- MS-01 디스크를 채우는 건 우리 데이터가 아니라 Docker(이미지·빌드캐시)다. 가끔
  `docker builder prune` / `image prune -a` 로 정리하면 된다(구동 중 컨테이너는 안전).
