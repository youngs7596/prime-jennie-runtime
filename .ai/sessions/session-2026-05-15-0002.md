## 중요 참고사항

### 본 세션의 architectural 학습

1. **prompt 의존 = anti-pattern** — 사용자가 직접 지적 ("뭔가 또 프롬프트와 패턴매칭 등 으로 해결을하고 있는거 같은데"). 처음 작성한 prompts.py 변경을 informational 톤으로 다운그레이드 + Strategy Engine 의 결정론 enforcement 로 교체. `feedback_prompt_control_limit` 메모리의 운영 데이터 검증.

2. **외톨이 path** = audit D1 가 "외부 매수" 라고 했지만 사실 v3 자체의 manual_sell 도 같은 안티패턴 (정상 path 의 책임 4단계를 일부만 수행). exit_executor 의 4단계 (tracker / recorder / notifier / publish_event) 를 동일하게 호출하는 것이 contract.

3. **two-layer enforcement 의 가치** — cooldown 가드를 fast_loop entry (cooldown_check.py) + slow_loop sheet 발행 (ActiveSheetChecker) 두 layer 에 둠. 두 logic 이 일치해야 drift 자동 검출 가능 (별도 batch 작업 후보).

4. **deploy 가 migration 적용 안 함** — 구조적 결함. 본 세션 수동 우회. 다음 세션 또는 P1 에 자동화 작업 필요.

5. **set -x + 비밀번호 leak** — 디버그 시도가 REDIS_PASSWORD 를 chat log 에 노출. chat log 가 외부로 안 새지만 best practice 로 회전 권장 (사용자 선택). 학습 - 환경 변수 expanded shell 명령 디버그 시 set -x 금지.
