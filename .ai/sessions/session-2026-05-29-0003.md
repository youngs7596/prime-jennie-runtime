# 세션 정리 — 2026-05-29-0003

검토 의뢰서(0002)에 대한 민지 응답을 받아, 최우선으로 정해진 P2.5(paper outcomes 측정 복구)를 구현한 세션. 민지가 판단 다섯을 줬고 영석님이 그중 실계좌 분리만 보류로 뒤집었다. P2.5 코드를 완성해 전체 테스트가 통과했고, "STOP 상태라 매매가 없으니 장중 배포가 무해하다"는 영석님 판단으로 장중에 배포했다.

## 1. 민지 검토 결과 + 영석님 결정

- **§3-4 P2 처리 승인**. 삭제 대상 6파일 중 라이브 의존 둘을 결정론 모듈로 이전한 처리가 정석이라고 인정. ground truth 단일화 + 결정론 코어 보존 + 매매 경로 0 변경.
- **§3-1 측정 복구를 P3 앞에**. 동의 + 세 가지 못박음 — (a) 진입가 결손 시트는 버리지 말고 `data_missing`으로 기록(커버리지가 alpha 신뢰도 메타데이터), (b) 배치를 per-row로 격리(한 건 NULL이 전체 롤백하는 구조 자체가 버그), (c) 측정 잡 실패 alert(심장이 멈췄는데 모니터가 없던 게 진짜 문제).
- **§3-2 실계좌 분리**. 민지는 A(분리) 권고 — 분리하면 §2-3·§2-4가 동시 해소. 그러나 **영석님이 보류**. STOP을 유지하면 되고 필요할 때 텔레그램으로 제어하는 게 편하다는 이유. 단 STOP 켜진 상태에선 텔레그램 청산도 막혀(`consumer.py:135-142`) 긴급 시 `/resume` 후 청산하거나 KIS 앱 직접이라는 점은 확인됨. 분리 대신 **설계 문서에 실계좌 두 종목 동결 상태를 명시**하기로 대체(아직 미작성 — 다음 세션 1순위).
- **§3-3 긴급 청산**. §3-2 보류와 무관하게 운영자 직접(KIS 앱 또는 `/resume` 후 텔레그램). STOP 우회 전용 경로 신설은 over-engineering이라 안 만든다.
- **§3-5 macro 게이트·latch**. 5-28 같은 정당한 closed는 국면 신호로 유지, 5-29처럼 macro가 open을 재판단했는데 reversal-guard latch가 막는 경우만 paper 한정 완화하되 "실거래였으면 closed였음"을 메타로 남겨 나중에 latch의 alpha 영향을 측정.
- **재정렬된 우선순위**: P2.5 측정복구 → P2.6 분봉 커버리지 교정 → P2.7 latch paper 완화 → P3 v1 정밀화 → P4 benchmark dashboard.

## 2. P2.5 한 일 — 측정 복구

진짜 원인은 둘이었다. `paper_outcomes.entry_price`의 NOT NULL 제약이 코드가 만들려던 data_missing 행(`entry_price=None`)을 거부했고, `_upsert_outcome` 호출이 격리돼 있지 않아 첫 실패가 잡 전체를 throw했다. 후보를 오래된 순으로 정렬하니 4-19 결손 시트가 맨 앞에서 첫 insert부터 터져 그 뒤 멀쩡한 시트는 시도조차 못 했다.

- **migration 023** (신규): `entry_price` NOT NULL 해제. 코드가 이미 만들던 data_missing outcome이 그대로 기록된다.
- **paper_outcomes.py**: `_upsert_outcome` 호출을 per-row try로 격리. 한 건 실패가 배치를 안 깬다.
- **app.py**: `h_paper_outcomes_daily`에서 잡이 예외로 죽으면 텔레그램 alert 후 re-raise(failed 기록 유지), errors>0이면 경고 alert. 진입가 결손은 이제 정상 측정이라 spam 아님. 하루 1회라 debounce 없음.
- **설계 문서 §4 정정**: "측정이 돌고 있다"는 전제를 "도입 후 5-29까지 0건이었고 P2.5로 복구"로. 거버넌스 룰대로 실측이 뒤집은 문서를 같이 고침.
- **테스트**: 한 시트 적재가 터져도 나머지가 측정되는지 재현. 기존 data_missing 테스트가 가짜 풀이라 실제 제약을 못 타고 통과했던 사각을, 가짜 풀이 특정 시트에서 일부러 터지게 해서 메움.

검증: ruff 통과, 전체 1451 통과(새 테스트 +1)·0 실패.
