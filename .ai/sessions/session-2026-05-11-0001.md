## 중요 참고사항

### 오늘의 큰 실수 (학습)

1. **`git checkout -- .` 으로 작업 사라뜨림** — 7 파일 변경 다 reset. 다시 작업 필요. → stage 안 한 work 상태에서 destructive 명령 절대 금지. `git add` 또는 `git stash` 먼저.

2. **Deploy 모니터 시간 필터 오류** — `createdAt > "2026-05-11T14:00:00Z"` 인데 deploy 가 13:54 UTC 였음. → `$(date -u)` 변수 사용으로 자동.

3. **paper/real 안전 게이트 도입 시 docker-compose.yml 의 env 누락** (가장 critical) — 코드만 추가하고 운영 env 전달 안 챙김 → kis-gateway crash loop. **"코드와 운영 env 가 양면" 인 변경은 한 PR 에 묶어야**. Agent prompt 에 이 점 명시 부족.

→ **메모리로 승격**: design 변경 시 코드 + 운영 env / compose / migration 양면 검증 필수.

### v2 scanner 포팅의 의미

오늘 가장 큰 성과 = v2 의 진입 시그널 (overextension, breakout, rsi 가드) 이 fast_loop 에 들어옴.
- 어제 sizing fix 가 종목당 사이즈를 5배 키웠다면
- 오늘 fix 는 진입 자체를 더 신중하게 (warm-up 5분 + RSI 가드 + breakout 확인)
- 두 fix 결합 효과 = "더 큰 사이즈로 더 신중하게 진입" — 5-12 가 첫 검증

### compose vs .env vs 코드의 양면 학습

`KIS_REAL_CONFIRMED` 사고가 보여준 패턴:
1. 코드 (`mode_safety.py`) 가 `os.environ` 에서 읽음
2. .env (MS-01) 에 값 설정
3. **docker-compose.yml 의 `environment:` 섹션에 명시 전달 필수** (환경 격리 — host env 가 자동으로 컨테이너 안에 들어가지 않음)

3번 누락 시 컨테이너는 env 못 봄. 모든 env 변수 도입 시 .env + compose 둘 다 챙겨야.
