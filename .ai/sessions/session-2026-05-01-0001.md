### 4) daily_asset_snapshot cron 근본 fix (commit `230d520`)

#### 진단 흐름

- `scheduled_job_runs` 9회 fail 패턴: 04-20~23 duration ~10-50ms (즉시 fail), 04-24~30 ~20s (0006 retry 적용 흔적)
- 핵심 단서: cron 시점 (06:45 UTC) 의 kis-gateway 로그에 **다른 컨테이너 (monitor 172.18.0.9) 의 `/api/balance` 호출은 200 OK 로 정상 응답** 중
- → kis-gateway 자체 문제 X, **job-worker → kis-gateway 만 fail**
- `docker exec prime-jennie-runtime-job-worker-1 env` → **`KIS_GATEWAY_URL` env 가 없음**
- `prime_jennie_runtime/infra/config.py:72` 의 `KISConfig.gateway_url` default 가 `"http://localhost:8080"` → 자기 자신 8080 connect 시도 → 즉시 ConnectError

#### Root cause

`docker-compose.yml` 의 job-worker `environment` 블록에 **`KIS_GATEWAY_URL` 만 누락**.
다른 KIS 의존 서비스 (fast-loop line 86, price-scheduler line 153, monitor line 395)
는 모두 명시되어 있음. job-worker 만 누락된 휴먼 에러.

0006 의 "장 마감 직후 일시 장애 + retry" 가설은 **틀린 진단**. retry 가 매번 즉시
fail 한 진짜 이유는 URL 자체가 잘못된 것 — 존재하지 않는 endpoint 로 retry 해도
결과는 항상 ConnectError.

#### Fix

```yaml
# docker-compose.yml job-worker environment 에 추가
KIS_GATEWAY_URL: http://kis-gateway:8080
```

0006 의 retry 코드 (5s/15s, 전용 client) 는 그대로 유지 — defense-in-depth.

#### Deploy + 검증

- commit `230d520` → push → GHCR Publish 33s success → Deploy 27s success
- MS-01 의 job-worker 컨테이너 재시작 확인: `KIS_GATEWAY_URL=http://kis-gateway:8080` 정상 주입
- 수동 호출 검증 (handoff 메모리의 backfill 템플릿) → 05-01 row 추가 (total_asset **207,181,315** = 약 2억 717만)
- `/api/portfolio/history?days=10` → 04-24, 04-25, **05-01** 3건 정상 노출

#### 잔여 한계

04-26~30 5일치는 **영구 결손**. KIS API 는 현재 잔고만 제공해 retroactive backfill 불가.
portfolio history 차트에 갭이 남지만 오늘부터는 cron 으로 자연 추가됨.
