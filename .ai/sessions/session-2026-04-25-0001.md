## 중요 참고사항

### 검증 루프의 핵심 원리

**1시간에 한 번 도는 로직 = 완전한 산출물 내야 한다** 는 사용자 원칙. 검증 루프는
이를 위한 구조. LLM 이 한 번에 완벽한 코드를 만들길 기대하지 않고, 샌드박스
실행 결과를 다시 LLM 에 먹여 자가 교정 기회를 3 회 줌. 같은 코드 반복은 즉시
break (의미 없는 호출 방지).

새로운 도구를 추가하지 않고 기존 `ScreeningToolAdapter.run()` (이미 있던 풍부한
ScreeningResult 반환) 을 그대로 활용. 즉 검증 = 실 실행이 같은 호출이라 비용 중복
없음.

### Qwen3 sentiment_score 의 위치

scout 피드는 **score 평균을 안 씀** (이번 PR). 그러나 Qwen3 가 추출한
`news_events.sentiment_score` 컬럼은 macro feeder (`slow_loop/macro/feeders/real.py`)
에선 정렬 기준으로 사용 중. 이건 "고임팩트 우선 → sentiment 절댓값 큰 것 → 최신순"
으로 macro 뉴스 상위 N건 골라내는 용도라 의미 다름. macro 피드는 안 건드림.

### candidates_count 컬럼의 함정

`scout_runs.candidates_count` 는 **LLM 의 expected_candidates** 임. 실제 row 수는
`SELECT COUNT(*) FROM screening_candidates WHERE scout_run_id = ?` 로 확인해야 함.
이번 세션에서 04-23 vs 04-24 비교 시 처음에 이 컬럼 보고 잘못된 결론 내릴 뻔함
(meta=12 actual=0 인데 12 인 줄). 모니터링/대시보드에서도 주의.

### ScreeningInvoker Protocol 변경

이번 PR 에서 `ScreeningInvoker` 에 `run()` 메서드가 추가됨 (이전엔 `invoke` 만).
`ScreeningToolAdapterStub` 와 `ScreeningToolAdapter` 둘 다 구현됨. 새 구현
