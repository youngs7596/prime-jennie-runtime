### 2.3 news pipeline false-positive 진단

사용자 보고: 같은 기사가 여러 종목 ticker 로 매핑됨 (SK온 7-ticker / 삼성물산-
신한지주 / 압구정-신한지주 / 엔비디아-NH투자증권 등).

**Root cause**:
1. 네이버 종목 뉴스 페이지가 시장/계열 뉴스를 함께 큐레이션
2. `crawler.crawl([ticker])` 가 ticker 별 별도 fetch + 결과 article 의 `ticker` 필드를
   강제 부여
3. `dedup.article_fingerprint = md5(source_url.lower())[:12]` — URL 에 `code={ticker}`
   referrer 가 박혀 ticker 마다 다른 fingerprint → dedup 통과 → 모두 저장
4. LLM extractor 는 prompt 에 ticker 를 input 으로 받기만, 검증 없음

**v2 비교**: v2 crawler 가 module-level `_seen_hashes` 로 헤드라인 정규화 hash
in-process dedup. v3 가 "dedup 책임은 파이프라인" 으로 옮기면서 URL-only fingerprint
로 약화 — 의도치 않은 회귀.

### 2.6 Pre-flight protocol 재설계

사용자: "내가 언제 기사를 찾아 읽고 있어, 니가 다 찾아서 해줘" — 사람 ground
truth 없는 protocol 로 재설계.

4 proxy metric (design §5):
1. **Title-coverage rate** — Agent ticker 가 title+body 에 substring/alias 매칭
   (precision proxy). gate ≥ 0.95
2. **Cluster reduction** — 알려진 FP cluster N건의 Agent 출력 ticker 수 평균.
   gate ≤ 1.5
3. **Cross-LLM Jaccard** (10건 한정) — Qwen3 ↔ DeepSeek tickers 일치
4. **Crawler overlap** — 정보용
