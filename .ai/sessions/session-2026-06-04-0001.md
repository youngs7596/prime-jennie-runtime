resume 로 6-3 세션이 남긴 6-4 검증을 돌리다가, 어제 "KIS 경고 사건 종결" 진단이 틀린

더 큰 단서 하나가 나왔다 — paper 모드인데 실전 앱키로 잔고를 조회하고 있다.

- **18시 측정 잡**: 정확히 18:00:00 에 돌아 9건을 측정(적재 1380→1389), 실패 0. 갇혀
  있던 시트들이 매일 측정 후보로 정상 진입한다(후보 41, 윈도우 열림 32). 어제 수리한
  "영구 도장" 버그 재발 없음.
- **분봉 수집**: 장중 5분 주기로 43종목, 적재 1290행, 실패 0. 옛 동결 명단이 아니라
  측정 대상 시트로 수집. 휴장일 가드도 6-3 에 정상 skip 확인됨.

## 2. 결정론 코어 첫 비교 분석 — 표본은 14건, 알파는 아직 음수

어제 "48건" 으로 본 건 진입일 기준 전체였고, 실제 측정 완료(벤치마크 비교 가능)는 14건
뿐이다. 나머지는 보유 중이거나 data_missing. 그래도 LLM 시기 baseline 과 처음 나란히
놓고 봤다 (`.ai/analyses/2026-06-04-decision-core-first-comparison.md`).

네 지표 모두 LLM 시기보다 나아졌다 — 평균 손익 -2.19%→-0.15%, 승률 35%→43%, 지수 이긴
비율 12%→29%, 손절 비대칭도 손절 -7.2%→-5.5% / 익절 +2.0%→+5.0% 로 크게 완화. 하지만
알파는 여전히 음수(-4.28%p)다. 시장이 +4.1% 오르는 동안 코어는 본전이었다. 덜 잃는 건
맞지만 강세장에서 시장을 따라잡는 지점까지는 아직 안 왔다. 5-26 fix 이후 구간(5건)은
알파 -0.69%p 로 좁혀졌으나 그 경계에서 시뮬레이터 방식도 바뀌어(daily_only→full) 원인을
가를 수 없다. 표본 14 라 신호 수준이고, KOSPI 필터까지 들어간 5-27+ 시트는 측정 완료가
아직 0건이라 이번엔 못 봤다.

## 3. KIS 경고 재진단 — 어제 진단이 틀렸다

**어제(6-3) 적은 두 가지가 모두 틀렸다.** (1) "외부 = 영석님 MTS 사용이 원인", (2)
"사건 종결, 6-4 경고 0건이면 확정". 6-4 에 경고/해제가 8회 반복됐고(09:34~15:11 KST,
오전 5회 집중), 사용자가 MTS 를 안 쓴다고 확인했다. 6-3 의 "30분 충돌 0" 은 휴장일
무부하라 의미 없는 측정이었다 — 첫 실부하 거래일인 오늘 충돌이 그대로 드러났다.

처음에 내가 "경고 0건" 이라 보고한 것도 틀렸다. 경고/해제 메시지는 컨테이너 로그가 아니라
Redis stream `v3:notifications` 에만 있는데 그걸 안 봤다. 표면 신호로 결론 낸 오판이었고
사용자 지적으로 바로잡았다.

**충돌원을 전수 조사해 모두 배제했다.** v3 내부(gateway 가 단일 비행 + 5초 캐시로 KIS 엔
잔고 폴당 1건만 보냄, WebSocket 은 시세 전용이라 원장 안 건드림), MS-01(v2 는 mariadb
컨테이너만 떠있고 앱 없음, family-mcp 는 KIS 무활동), 로컬 WSL(KIS 무접속). gateway
로그상 경고 직전 90초의 KIS 호출은 monitor 단독 30초 폴뿐인데 **첫 시도부터** 거부됐다.
우리 호출량이 바닥인데 거부당한 것이다.

**가장 큰 단서 (6-4 발견): paper 모드인데 실전 앱키로 잔고를 조회하고 있다.** gateway 가
KIS 로 보낸 잔고 조회 주소가 `openapi.koreainvestment.com:9443` (실전 도메인), 계좌
68211289 였다. 글로벌 메모리상 paper 는 `openapivts:29443` 의 별도 앱키여야 하고, 실전
앱키는 v2 가 쓰던 단일 세트다. 즉 v3 가 실전(=v2 와 공유하는) 앱키로 실계좌 잔고를 폴링
중이다. 이게 의도된 구조인지(조회는 실계좌, 매매만 차단) 설정 오류인지, 그리고 같은
앱키를 v2 나 다른 무언가가 또 쓰는지는 아직 모른다. EGW00201 의 유력한 새 후보다.

**해결이 아니라 원인 확정을 위한 조치를 배포했다 (3bcbaf5).** KIS 거부 응답의 한글
사유(msg1)를 코드가 읽고도 버려서 원인을 구분 못 했다. 재시도 로그와 재시도 소진 로그
두 곳에서 msg1 을 남기게 고쳤다(`kis_api.py` `_kis_reject_detail`). 소진 시점은 지금까지
HTTP 500 예외로 바뀌며 사유가 사라지던 자리다. 빌드·배포 성공, MS-01 gateway 재기동
확인. 다음 거래일에 거부가 나면 "초당 거래건수 초과"(한도) vs "관문 혼잡/일시 오류"(KIS
부하) 가 로그에 한국어로 갈린다.

- **"외부 MTS 가 원인" 으로 다시 단정하지 말 것.** 6-4 에 기각됨. 원인 미확정.

- KIS 호출 로그는 남지만 거부 사유 본문(msg1)은 3bcbaf5 전까지 버려졌다. 6-5 부터 남는다.
- 잔고·주문 계열 새 소비자는 반드시 `infra/balance_snapshot.py` reader 경유. gateway
  HTTP 직접 호출 금지.
